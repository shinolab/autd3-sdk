## 読み出し結果の型

`read_firmware_version()` / `read_fpga_state()` / `read_telemetry()` はデバイス番号順に 1 台 1 要素の配列を返す.
`Lost` のデバイスがある間は `DeviceLost` で失敗する.

Python のメソッド・フィールド名は Rust と同じ (フィールドはプロパティ).
C# は PascalCase のプロパティになる (`is_thermal_asserted()` → `IsThermalAsserted`, `fifo_drop` → `FifoDrop` など).

### FirmwareVersion

| メンバ                  | 型               | 説明                                                   |
| ----------------------- | ---------------- | ------------------------------------------------------ |
| `cpu`                   | `Version`        | CPU ファームウェアのバージョン                         |
| `fpga`                  | `Version`        | FPGA ファームウェアのバージョン (読めなければ `0.0.0`) |
| `is_emulator()`         | `bool`           | デバイスエミュレータか                                 |
| `is_supported()`        | `bool`           | CPU と FPGA の両方がこの SDK のサポートする系列か      |
| `SUPPORTED_SERIES`      | `(u8, u8)`       | サポートする系列 (major, minor) (C#: `SupportedSeries`) |

`Version` は `major` / `minor` / `patch` (`u8`) と `is_unknown()` (`0.0.0` か) を持つ.

| メソッド                  | 型               | 説明                                     |
| ------------------------- | ---------------- | ---------------------------------------- |
| `raw()`                   | `u8`             | 状態レジスタの生の値                     |
| `is_thermal_asserted()`   | `bool`           | 温度センサが閾値を超えているか           |
| `current_mod_bank()`      | `ModulationBank` | 現在の Modulation bank                   |
| `current_pattern_bank()`  | `PatternBank`    | 現在の Pattern bank (Pattern と STM で共有) |
| `is_pattern_mode()`       | `bool`           | Pattern を出力しているか                 |
| `is_stm_mode()`           | `bool`           | STM を出力しているか                     |
| `is_pattern_stopped()`    | `bool`           | Pattern / STM の再生が止まっているか |
| `is_mod_stopped()`        | `bool`           | Modulation の再生が止まっているか |

| `is_failsafe_active()`    | `bool`           | フェイルセーフで出力が止まっているか     |

### Telemetry

CPU の診断カウンタ. `Clear` で `boot_failure` 以外は 0 に戻る (`Client` は開くときに `Clear` を送る).
読み出してもクリアされない.

| フィールド            | 型    | 説明                                                   |
| --------------------- | ----- | ------------------------------------------------------ |
| `fifo_drop`           | `u32` | 受信 FIFO が満杯で捨てたフレーム数                     |
| `dedup`               | `u32` | 重複として捨てたフレーム数                             |
| `seq_mismatch`        | `u32` | シーケンス番号が合わず無視したフレーム数               |
| `dispatch_error`      | `u32` | 処理がエラーになった回数                               |
| `processed`           | `u32` | 処理したフレーム数                                     |
| `send_failure`        | `u32` | NIC が送信を断った回数                                 |
| `failsafe`            | `u16` | ホストとの通信途絶によるフェイルセーフの発火回数       |
| `ptp_unlock_failsafe` | `u16` | PTP ロック喪失によるフェイルセーフの発火回数           |
| `sync_resync`         | `u8`  | 同期入力のハード再同期回数 (`Synchronize` で 0 に戻る) |
| `boot_failure`        | `u8`  | 起動時に失敗した手順の数 (`Clear` で消えない)          |
| `cpu_watchdog`        | `u8`  | CPU ウォッチドッグの発火回数 (FPGA の再構成まで消えない) |

`u32` のフィールドは桁あふれで 0 に戻り, `u16` / `u8` のフィールドは上限で止まる.

## ClientConfig

<CodeTabs rust={excerpt(open, "config")} python={excerpt(pyOpen, "config")} csharp={excerpt(csOpen, "config")} />

| フィールド             | 型                    | デフォルト          | 説明                                                       |
| ---------------------- | --------------------- | ------------------- | ---------------------------------------------------------- |
| `ack_timeout`          | `Duration`            | 10 ms               | 応答待ちのタイムアウト. 過ぎると送信中のフレームは `Timeout` で失敗する. |
| `max_inflight`         | `NonZeroUsize`        | `7`                 | 応答を待たずに送ってよいフレーム数 (stream送信用)           |
| `max_resync_rounds`    | `NonZeroU32`          | `8`                 | デバイスとの足並みを揃え直す試行の回数上限                 |
| `require_supported_firmware` | `bool`          | `false`             | `true`なら接続時にファームウェアがサポートされているか検査する |
| `resynchronize_on_recovery` | `Option<NonZeroU32>` | `Some(3)`       | `Lost` から自動復帰したデバイスへ, 次の送信の前に `Synchronize` を送り直す. 値は試行回数の上限で, `None` なら送らない ([状態監視](/autd3-sdk/guide/state-check/) 参照) |
| `release_failsafe_on_recovery` | `Option<NonZeroU32>` | `Some(3)`    | `Lost` から自動復帰したデバイスへ, 次の送信の前に `ReleaseFailsafe` を送り, フェイルセーフで止まった出力を再開させる. 値は試行回数の上限で, `None` なら送らない ([状態監視](/autd3-sdk/guide/state-check/) 参照) |
| `exec_lead`           | `Option<Duration>`  | `None` | 送信したフレームを全デバイスが同じ時刻に処理し始めるようにする (後述). `None` で各デバイスが届いた順にすぐ処理する |

`max_inflight` は `MAX_INFLIGHT (7)` (Python: `autd3.params.MAX_INFLIGHT`, C#: `Params.MaxInflight`) を超えるとエラーになる.
既定値も `MAX_INFLIGHT` で, これは各デバイスの受信キューのフレーム数 `DEVICE_QUEUE_FRAMES` (Python: `autd3.params.DEVICE_QUEUE_FRAMES`, C#: `Params.DeviceQueueFrames`) に等しい.
`ack_timeout` を 0 にすると, `Client` を開くときにエラー (`InvalidConfig`. Python の `Autd3Error.code` は `INVALID_ARGUMENT`, C# の `Autd3Exception.Code` は `InvalidArgument`) になる.
Python の既定値は Rust と同じで, `None` を渡せるのは型が `Option` の `resynchronize_on_recovery` / `release_failsafe_on_recovery` だけである.

再送処理は行われない. 失敗したコマンドはユーザが送り直す必要がある.

### exec_lead

デバイスへ送信は順に 1 台ずつ行われるので, 各デバイスにフレームが届く時刻は少しずつずれる.
`exec_lead` を指定すると, 送信の際に「デバイスの現在時刻 + `exec_lead`」 を 1 µs 単位に切り上げた時刻を送信し, 各デバイスはその時刻まで処理を待つ.
これにより, 1 回の送信の内容を全デバイスが同じタイミングで処理し始める.

注意点は以下の通り
- 必ず全デバイスが同じ時刻に処理を始めることを保証はしない
  - 送信の完了が `exec_lead` 以内に終わらなければ, 遅れたデバイスは指定時刻を過ぎてから処理する. この回数は `read_telemetry` の `exec_late` で読める.
  - streaming で送ると, 前のフレームの処理中に次のフレームの指定時刻が来ることがあり, そのフレームは遅れて処理される (`exec_late` にカウントされる).
  - また, 成功したとしてもCPUボード内部の処理の開始が揃うだけであり, FPGAの処理の開始が揃うこと (すなわち, 出力される超音波の位相の更新タイミングが揃うことなど) は保証しない
- 送信完了が`exec_lead` だけ遅れる
- 100 µs 以上, 2^31 µs (約 35.8 分) 未満でなければならない. また, [`UdpOption`](/autd3-sdk/api/basics/transport-option/) の `lost_timeout` 未満でなければならない
- `ack_timeout` (既定 10 ms) は `exec_lead` + 処理時間より長くする

### 処理時刻の上書き

`exec_lead` は全てのフレームに同じ規則で処理時刻を付ける.
特定のフレームだけ別の処理時刻にするには, `send_frame_at` に `ExecAt` を渡して送る.
`send` / `send_streaming` / `send_frame` は `exec_lead` に従う.

<CodeTabs rust={excerpt(methods, "exec_at")} python={excerpt(pyMethods, "exec_at")} csharp={excerpt(csMethods, "exec_at")} />

| `ExecAt`         | 処理時刻                                                                 |
| ---------------- | ------------------------------------------------------------------------ |
| `Immediate`      | 付けない (`exec_lead` を指定していても, 届いた順にすぐ処理する)          |
| `Lead(lead)`     | デバイスの現在時刻 + `lead` (このフレームだけ `exec_lead` の代わりに使う) |
| `At(sys_time)`   | デバイス時刻 `sys_time` ([SysTime](/autd3-sdk/api/basics/sys-time/) 参照) |

- `Lead` の値の範囲は `exec_lead` と同じ (100 µs 以上, 2^31 µs 未満, `lost_timeout` 未満). 外れると `InvalidPayload` で, そのフレームは送られない
- `At` は現在時刻より 2^31 µs 以上先・2^30 µs (約 17.9 分) 以上前, または `lost_timeout` 以上先だとエラーになる. 過ぎた時刻 (範囲内) は受け付け, デバイスはすぐに処理して `exec_late` に数える
- `ack_timeout` (既定 10 ms) は, 送信から指定時刻までの時間 + 処理時間より長くする
- `Lead` / `At` はデバイスの時刻が分からない (時刻を載せた返信をまだ受けていない) と `DeviceTimeUnknown` で失敗する
