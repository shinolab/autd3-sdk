| メソッド                  | async | 返り値                                 | 説明                                                       |

| `num_devices()`           | —     | `usize`                                | 接続中のデバイス台数                                       |

| `send_frame_at(frame, exec)` | ✓  | `Result<ResponseFuture, Error>`       | 処理時刻を指定してフレームを 1 つ送る ([処理時刻](#処理時刻) 参照) |
| `device_status()`         | —     | `Result<Vec<DeviceStatus>, Error>`     | 各デバイスの状態. 詳細は[状態監視](/autd3-sdk/guide/state-check/)を参照. |
| `send_heartbeat()`        | —     | `Result<(), Error>`                   | `Lost` でない全デバイスへ生存確認を 1 回送る ([フェイルセーフ](/autd3-sdk/guide/failsafe/#通信途絶の-failsafe-と生存確認) 参照) |
| `close()`                 | —     | `Result<(), Error>`                   | 接続を閉じる                                               |

`close()` は I/O スレッドを止めて接続を閉じるだけで, デバイスへは何も送らない.
デバイスは閉じた後も直前の出力を続けるので, 出力を止めるのはユーザーの責任である.

## streaming

`send` は 1 フレームずつ応答を待つ (stop-and-wait).
応答を待たずに続けて送るには, `Frames::encode` でコマンドをフレーム列に変換し, `send_frame` が返す `ResponseFuture` を貯めてから順に await する.

<CodeTabs rust={excerpt(sample, "streaming")} python={excerpt(pySample, "streaming")} csharp={excerpt(csSample, "streaming")} />

応答を待たずに送ってよいフレーム数は `MAX_INFLIGHT (7)` である.
`MAX_INFLIGHT` 個のフレームが応答待ちの間, `send_frame` は応答が揃ってどれかが空くまで待つ.

## 読み出し結果の型

`read_firmware_version()` / `read_fpga_state()` / `read_telemetry()` はデバイス番号順に 1 台 1 要素の配列を返す.
`Lost` のデバイスがある間は `DeviceLost` で失敗する.

### FirmwareVersion

| メンバ                  | 型               | 説明                                                   |
| ----------------------- | ---------------- | ------------------------------------------------------ |
| `cpu`                   | `Version`        | CPU ファームウェアのバージョン                         |
| `fpga`                  | `Version`        | FPGA ファームウェアのバージョン                        |
| `is_emulator()`         | `bool`           | デバイスエミュレータか                                 |
| `is_supported()`        | `bool`           | CPU と FPGA の両方がこの SDK のサポートする系列か      |
| `SUPPORTED_SERIES`      | `(u8, u8)`       | サポートする系列 (major, minor)                        |

### FpgaState

| メソッド                  | 型               | 説明                                     |
| ------------------------- | ---------------- | ---------------------------------------- |
| `is_thermal_asserted()`   | `bool`           | 温度センサが閾値を超えているか           |
| `current_mod_bank()`      | `ModulationBank` | 現在の Modulation bank                   |
| `current_pattern_bank()`  | `PatternBank`    | 現在の Pattern bank (Pattern と STM で共有) |
| `is_pattern_mode()`       | `bool`           | Pattern を出力しているか                 |
| `is_pattern_stopped()`    | `bool`           | Pattern / STM の再生が止まっているか |
| `is_mod_stopped()`        | `bool`           | Modulation の再生が止まっているか |
| `is_transition_pending()` | `bool`           | bank の切り替えが発効待ちか              |

### Telemetry

CPU の診断カウンタ.

| フィールド            | 型    | 説明                                                   |
| --------------------- | ----- | ------------------------------------------------------ |
| `fifo_drop`           | `u32` | 受信 FIFO が満杯で捨てたフレーム数                     |
| `dispatch_error`      | `u32` | 処理がエラーになった回数                               |
| `processed`           | `u32` | 処理したフレーム数                                     |
| `send_failure`        | `u32` | NIC が送信を断った回数                                 |
| `failsafe`            | `u16` | ホストとの通信途絶によるフェイルセーフの発火回数       |
| `ptp_unlock_failsafe` | `u16` | PTP ロック喪失によるフェイルセーフの発火回数           |
| `sync_resync`         | `u8`  | 同期入力のハード再同期回数 (`Synchronize` で 0 に戻る) |
| `boot_failure`        | `u8`  | 起動時に失敗した手順の数 (`Clear` で消えない)          |
| `cpu_watchdog`        | `u8`  | CPU ウォッチドッグの発火回数 (FPGA の再構成まで消えない) |
| `exec_late`           | `u32` | [処理時刻](#処理時刻)を 1 µs 以上過ぎてから処理を始めたフレーム数 |

## 処理時刻

デバイスへの送信は順に 1 台ずつ行われるので, 各デバイスにフレームが届く時刻は少しずつずれる.
`send_frame_at` に `ExecAt` を渡して送ると, フレームに処理時刻を付け, 各デバイスはその時刻まで処理を待つ.
これにより, 1 回の送信の内容を全デバイスが同じタイミングで処理し始める.
`send` / `send_frame` は処理時刻を付けない (各デバイスは届いた順にすぐ処理する).
コマンドを処理時刻付きで送るには, `Frames::encode` でフレーム列に変換し, 各フレームを `send_frame_at` で送る.

<CodeTabs rust={excerpt(methods, "exec_at")} python={excerpt(pyMethods, "exec_at")} csharp={excerpt(csMethods, "exec_at")} />

| `ExecAt`         | 処理時刻                                                                 |
| ---------------- | ------------------------------------------------------------------------ |
| `Immediate`      | 付けない (届いた順にすぐ処理する. `send_frame` と同じ)                    |
| `Lead(lead)`     | 送信時のデバイスの現在時刻 + `lead`                                       |
| `At(sys_time)`   | デバイス時刻 `sys_time` ([SysTime](/autd3-sdk/api/basics/sys-time/) 参照) |

注意点は以下の通り
- 必ず全デバイスが同じ時刻に処理を始めることを保証はしない
  - 全デバイスへの送信が指定時刻までに終わらなければ, 遅れたデバイスは指定時刻を過ぎてから処理する. この回数は `read_telemetry` の `exec_late` で読める.
  - 応答を待たずに続けて送ると ([streaming](#streaming)), 前のフレームの処理中に次のフレームの指定時刻が来ることがあり, そのフレームは遅れて処理される (`exec_late` にカウントされる).
  - また, 成功したとしてもCPUボード内部の処理の開始が揃うだけであり, FPGAの処理の開始が揃うこと (すなわち, 出力される超音波の位相の更新タイミングが揃うことなど) は保証しない
- 応答は処理の後に返るので, 送信の完了は指定時刻まで遅れる. 1 フレームずつ応答を待つと, 複数フレームのコマンドはフレーム数 × `lead` 程度かかる

## each

`each` はデバイスを引数にするクロージャを受け取り, デバイスごとに異なる 1 フレームのコマンドを割り当てる.

<CodeTabs rust={excerpt(sample, "each")} python={excerpt(pySample, "each")} csharp={excerpt(csSample, "each")} />

`each` は常に 1 フレームになる.
`Modulation` / `FociStm` / `PatternStm` のような複数フレームのコマンドは `each` では送れない.
デバイスごとに異なる複数フレームの内容が必要な場合, `Frame::new` でフレームを自分で組み立てて `send_frame` で送る.

Rust ではクロージャの返り値はすべて同じ型でなければならない.
型の異なるコマンドを混在させたい場合は, `Box<dyn Operation>` に揃える.
