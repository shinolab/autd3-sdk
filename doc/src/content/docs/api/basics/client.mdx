`Client` はコマンドの送信・状態の読み出しを行う中心的なオブジェクト.
`Client` を含む基礎・コマンドの API は本体パッケージが提供する.
接続先 (実機・[デバイスエミュレータ](/autd3-sdk/api/connection/device-emulator/)・Simulator) は [`TransportOption`](/autd3-sdk/api/connection/) で指定する.

`Client` を開く前に [`Driver`](/autd3-sdk/api/basics/driver/) を開いて回し始める必要がある.
`Driver::open` が返す `Connector` を `Client::open` に渡す.
ライブラリは送受信のためのスレッドを立てないので, `Driver` を回さずに `Client::open` を await すると返らない.

## API

<CodeTabs rust={excerpt(methods, "api")} python={excerpt(pyMethods, "api")} csharp={excerpt(csMethods, "api")} />

| メソッド                  | async | 返り値                                | 説明                                                       |
| ------------------------- | :---: | ------------------------------------- | ---------------------------------------------------------- |
| `num_devices()`           | —     | `usize`                               | 接続中のデバイス台数                                       |
| `geometry()`              | —     | `&Geometry`                           | 接続時のデバイスの物理配置                                 |
| `read_firmware_version()` | ✓     | `Result<Vec<FirmwareVersion>, Error>` | 各デバイスの CPU/FPGA ファームウェアバージョン             |
| `read_fpga_state()`       | ✓     | `Result<Vec<FpgaState>, Error>`       | 各デバイスの FPGA 状態                                     |
| `datagram_builder()`      | —     | `DatagramBuilder`                     | [DatagramBuilder](/autd3-sdk/api/basics/datagram-builder/) |
| `send(frame)`             | ✓     | `Result<ResponseFuture, Error>`       | フレームを送信キューにいれる. `ResponseFuture` を await すると応答 (`Response`) が得られる |
| `send_checked(frame)`     | ✓     | `Result<(), Error>`                   | 送信し, 応答確認まで行う                                   |
| `stop()`                  | ✓     | `Result<(), Error>`                   | 全振動子を停止                                             |
| `close()`                 | ✓     | `Result<(), Error>`                   | 全振動子を停止して接続を閉じる                             |

`send_checked(frame).await?` は, `send(frame).await?.await?.check()` と等価である.

## ClientConfig

<CodeTabs rust={excerpt(open, "config")} python={excerpt(pyOpen, "config")} csharp={excerpt(csOpen, "config")} />

| フィールド             | 型                    | デフォルト          | 説明                                                       |
| ---------------------- | --------------------- | --------------- | ---------------------------------------------------------- |
| `ack_timeout`          | `Duration`            | 10 ms           | 応答待ちのタイムアウト. 過ぎると送り直す                   |
| `max_inflight`         | `NonZeroUsize`        | `7`             | 応答を待たずに送ってよいフレーム数 (既定はデバイスの受信キューの容量) |
| `max_resync_rounds`    | `NonZeroU32`          | `8`             | 再同期を試みる最大ラウンド数                               |
| `low_latency`          | `bool`                | `false`         | 低レイテンシモード          |
| `validate_state`       | `bool`                | `true`          | 送信前検証を有効にする                     |
| `require_supported_firmware` | `bool`          | `false`         | `true`なら接続時にファームウェアがサポートされているか検査する |

`max_inflight` は `MAX_INFLIGHT (127)` を超えるとエラーになる.
デバイスの受信キューは 7 フレーム分なので, 既定値より大きくしても速くはならない (溢れたフレームは送り直しになる).

`low_latency` を有効にすると, ファームウェア内部での受信バッファをバイパスするため, レイテンシが改善する. ただし, 動作が不安定になる可能性がある.
