`Client` はコマンドの送信・状態の読み出しを行う中心的なオブジェクト.
`Client` を含む基礎・コマンドの API は本体パッケージが提供する.
接続先 (実機・[デバイスエミュレータ](/autd3-sdk/api/connection/device-emulator/)・Simulator) は [`TransportOption`](/autd3-sdk/api/connection/) で指定する.

`Client::open` はデバイスを列挙して開き (同期的に行われる), 受信と生存確認のための I/O スレッドを 1 本起こしてから, 接続の手順 (handshake) を進める.
ユーザーがスレッドを立てたりループを回したりする必要は無い.

Python の `Client.open` / `send` / `close` などの非同期 API は, 実行中の asyncio イベントループの中 (`asyncio.run(main())` で起動したコルーチンの中など) からしか呼べない.
同期版の API は提供していない.

## API

<CodeTabs rust={excerpt(methods, "api")} python={excerpt(pyMethods, "api")} csharp={excerpt(csMethods, "api")} />

| メソッド                  | async | 返り値                                | 説明                                                       |
| ------------------------- | :---: | ------------------------------------- | ---------------------------------------------------------- |
| `num_devices()`           | —     | `usize`                               | 接続中のデバイス台数                                       |
| `geometry()`              | —     | `&Geometry`                           | 接続時のデバイスの物理配置                                 |
| `bus_stats()`             | —     | `BusStats`                            | 送受信の統計 (送信フレーム数・ack 遅延など)                |
| `read_firmware_version()` | ✓     | `Result<Vec<FirmwareVersion>, Error>` | 各デバイスの CPU/FPGA ファームウェアバージョン             |
| `read_fpga_state()`       | ✓     | `Result<Vec<FpgaState>, Error>`       | 各デバイスの FPGA 状態                                     |
| `send(cmd)`               | ✓     | `Result<(), Error>`                   | コマンドを送信し, 1 フレームずつ応答確認まで行う           |
| `send_streaming(cmd)`     | ✓     | `Result<StreamFuture, Error>`         | 応答を待たずに窓の範囲でフレームを送る. `StreamFuture` を await すると全フレームの完了を待つ |
| `send_frame(frame)`       | ✓     | `Result<ResponseFuture, Error>`       | フレームを 1 つ送る. `ResponseFuture` を await すると応答 (`Response`) が得られる |
| `state_checker()`         | —     | `StateChecker`                        | デバイスの状態を読むためのハンドル ([状態監視](/autd3-sdk/guide/state-check/)) |
| `silent_stop()`           | ✓     | `Result<(), Error>`                   | Silencer を設定してから全振動子を停止                      |
| `close()`                 | ✓     | `Result<(), Error>`                   | `silent_stop()` と同じ手順で停止して接続を閉じる           |

`silent_stop()` は, 振幅を一気に落としてノイズが出るのを避けるため, まず [Silencer](/autd3-sdk/api/command/silencer/) を既定の完了時間 (strict mode は無効) に設定してから全振動子の振幅を 0 にする.
Silencer の設定は上書きされたままになるので, 別の設定で出力を再開する場合は `SetSilencer` を送り直すこと.

`bus_stats()` が返す `BusStats` は接続と統計を共有するハンドルで, 値を読むたびにその時点の統計が得られる (取り直す必要は無く, `Client` を閉じた後も読める).

送信の詳細は [送信](/autd3-sdk/api/basics/send/) を参照.
ライブラリのログを表示する方法は [ログ出力](/autd3-sdk/api/basics/tracing/) を参照.

## ClientConfig

<CodeTabs rust={excerpt(open, "config")} python={excerpt(pyOpen, "config")} csharp={excerpt(csOpen, "config")} />

| フィールド             | 型                    | デフォルト          | 説明                                                       |
| ---------------------- | --------------------- | --------------- | ---------------------------------------------------------- |
| `ack_timeout`          | `Duration`            | 10 ms           | 応答待ちのタイムアウト. 過ぎると送信中のフレームは `Timeout` で失敗し, 次の送信で SEQ を揃え直す |
| `max_inflight`         | `NonZeroUsize`        | `7`             | 応答を待たずに送ってよいフレーム数 (既定はデバイスの受信キューの容量) |
| `max_resync_rounds`    | `NonZeroU32`          | `8`             | SEQ を揃え直す `Reset` を送り直す最大回数                  |
| `require_supported_firmware` | `bool`          | `false`         | `true`なら接続時にファームウェアがサポートされているか検査する |

`max_inflight` は `MAX_INFLIGHT (7)` を超えるとエラーになる.
これはデバイスの受信キューの容量で, これより多く送ると溢れたフレームが捨てられるためである.
自動再送は行わない. 失敗したコマンドは呼び出し側が送り直す ([送信](/autd3-sdk/api/basics/send/) 参照).
