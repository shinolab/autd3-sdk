`WriteFociBuffer` は, Foci STM 用の焦点列をバンクへ書き込む低レベルコマンド.

## API

<CodeTabs rust={excerpt(sample, "write")} python={excerpt(pySample, "write")} csharp={excerpt(csSample, "write")} />

| フィールド     | 型                    | 説明                               |
| -------------- | --------------------- | ---------------------------------- |
| `bank`         | `PatternBank`         | 書き込み先バンク                   |
| `start_index` | `usize`               | バンク内の書き込み開始インデックス |
| `points`       | `&[ControlPoints]`    | 焦点サンプルの列                   |

`ControlPoints` は焦点 (`ControlPoint`) の列と振幅を持つ 1 サンプル. 焦点数は全サンプルで揃える.
詳細は [FociStm](/autd3-sdk/api/command/foci-stm/#controlpoint--controlpoints) を参照.

`WriteFociBuffer` は 1 フレームで送られ, 1 フレームに収まる分しか書けない.
上限 (`ControlPoints` の数) は焦点数で変わり, Rust では `WriteFociBuffer::max_len(num_foci)`, Python では `WriteFociBuffer.max_len(num_foci)`, C# では `WriteFociBuffer.MaxLen(numFoci)` で, 超えると送信時にエラーになる.
それより長い焦点列は `start_index` を上限ずつずらして分割して送る (高レベルの [FociStm](/autd3-sdk/api/command/foci-stm/) はこの分割を自動で行う).
1 フレームのコマンドなので, [each](/autd3-sdk/api/basics/client/#each) でデバイスごとに異なる焦点列を割り当てられる.

## Example

`WriteFociBuffer` → `ConfigFociStm` → `ActivatePatternBank` で焦点列を Foci STM として再生する例 (高レベルの [FociStm](/autd3-sdk/api/command/foci-stm/) と等価). 200 点は 1 フレームに収まらないので分割して書き込む.
