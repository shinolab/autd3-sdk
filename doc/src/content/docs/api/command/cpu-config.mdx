`SetCpuConfig` は, CPU ファームウェアが内部で使う設定値 (failsafe・ウォッチドッグ・PTP 同期のパラメータなど) を変更するコマンド.

:::caution
`failsafe_timeout`, `ptp_unlock_failsafe_timeout` 以外は通常変更する必要はない.
これら以外を既定値から変更した場合の動作は保証しない.
:::

### CpuConfig

| フィールド                   | 型           | 既定値        | 説明 |
| ---------------------------- | ------------ | ------------- | ---- |
| `sync_guard`                 | `Duration`   | 250 μs        | 同期開始時刻の選択マージン                                                   |
| `failsafe_timeout`           | `Option<Duration>` | `None`  | ホストからの通信がこの時間途絶えるとデバイスが出力を止める (failsafe). `None` は failsafe 無効 |
| `ptp_unlock_failsafe_timeout` | `Option<Duration>` | `None` | PTP のロックを失ったままこの時間が経つと, そのデバイスが出力を止める. `None` は無効 |
| `fpga_bus_wait`              | `FpgaBusWait` | `Cycles3`    | CPU が FPGA を読み書きするバスのウェイト周期数. `Cycles2` または `Cycles3` |
| `cpu_watchdog_timeout`       | `Option<Duration>` | 1 s     | CPU ファームウェアがこの時間止まると出力を止める. `None` は無効 |
| `ptp`                        | `PtpConfig`  |               | PTP 同期のパラメータ |

### PtpConfig

| フィールド             | 型           | 既定値  | 説明 |
| ---------------------- | ------------ | ------- | ---- |
| `sync_interval`        | `Duration`   | 8 ms    | `Sync` メッセージの送出間隔 |
| `tx_timestamp_timeout` | `Duration`   | 3 ms    | `Delay_Req` の送信タイムスタンプの回収待ち上限 |
| `delay_resp_timeout`   | `Duration`   | 6 ms    | `Delay_Resp` の待ち上限 |
| `holdover`             | `Duration`   | 1 s     | ロック中に `Sync` を受けられないままロックを保つ時間 |
| `lock_samples`         | `NonZeroU16` | 64      | ロックに必要な連続標本数 |
| `step_threshold`       | `Duration`   | 10 μs   | 時刻のずれがこれを超えたら時計を強制的に揃える |
| `lock_threshold`       | `Duration`   | 100 ns  | 時刻のずれがこれ未満の標本をロックに数える |
| `kp_milli`             | `u32`        | 50      | サーボの比例ゲイン × 1000 |
| `ki_milli`             | `u32`        | 1       | サーボの積分ゲイン × 1000 |
| `max_freq_ppb`         | `u32`        | 500,000 | 周波数補正の上限 [ppb]. 0 から 2,147,483,647 (超えるとデバイスが拒否する) |
| `delay_req_syncs`      | `NonZeroU16` | 32      | ロック後に経路遅延を測り直す間隔 (`Sync` の回数) |
| `path_delay_filter_shift` | `u8`      | 5       | 経路遅延の平滑化の係数 `1 / 2^n`. 0 から 16 (超えるとデバイスが拒否する). 0 で平滑化しない |
| `pause_quanta`         | `Option<NonZeroU16>` | 48 | 回線が飽和したときにホストへ送られる `PAUSE` の長さ [512 ビット時間]. `None` で `PAUSE` を送らない |
| `pause_hold_syncs`     | `u16`        | 64      | 一度詰まってから, 送信のたびに `PAUSE` を送り続ける `Sync` の回数 |
| `pause_retry`          | `Duration`   | 8 ms    | `Sync` を送り出せない間, `PAUSE` を送り続ける時間 |

C# では `Duration` の項目を `TimeSpan` で渡すので, 100 ns 単位でしか指定できない (`lock_threshold` の既定値 100 ns は `TimeSpan.FromTicks(1)`).

:::danger
`failsafe_timeout` は既定で `None` (無効) で, ホストのクラッシュやケーブル断で通信が途絶えてもデバイスは超音波を出力し続ける.
途絶えたときに出力を止めたい場合は `failsafe_timeout` を指定する.
指定した場合, 送るものが無い間は [`send_heartbeat()`](/autd3-sdk/api/basics/client/#生存確認) を周期的に呼び, `failsafe_timeout` はその間隔の 2 倍より十分長く保つこと. 短すぎるとホストが動いていても出力が止まる.
`ptp_unlock_failsafe_timeout` を指定すると, PTP のロックを失ったデバイス (先頭のデバイス以外) は, 失ってからこの時間が経つと failsafe と同じ方法で出力を止める.
再ロックには既定の設定で 1 s 程度かかるので, それより短い値を指定するとロックを失うたびに必ず出力が止まる.

`cpu_watchdog_timeout` は, CPU ファームウェアのハングやリセット中に FPGA が出力を止めるまでの時間で, failsafe と同じ方法で出力を止める.
`None` にすると, CPU ファームウェアが止まってもデバイスは止まる直前の出力を続ける.

`failsafe_timeout` を指定したままクライアントを閉じると, ホストからの通信が途絶えるのでその時間の後に出力が止まる.
次に開いたときは [`ReleaseFailsafe`](/autd3-sdk/api/command/release-failsafe/) か [Clear](/autd3-sdk/api/command/clear/) を送る.

failsafe や CPU ウォッチドッグで止まった出力は, 自動では戻らない.
止まっているかどうかは `read_fpga_state()` が返す `FpgaState` の `is_failsafe_active()` (C#: `IsFailsafeActive`) で確認できる.
[`ReleaseFailsafe`](/autd3-sdk/api/command/release-failsafe/) コマンドを送ると出力が再開される.
[Clear](/autd3-sdk/api/command/clear/) でも解除されるが, すべての状態が既定値に戻る.
:::

設定値は [Clear](/autd3-sdk/api/command/clear/) と電源再投入で既定値に戻る.
クライアントを開き直しても戻らない (前のセッションの値のまま動く) ので, 既定値に戻したい場合は `Clear` を送る.
PTP がロックしない値を入れたまま閉じると, 次に開くときの同期待ちが `open_timeout` で失敗する (`SyncTimeout`).
その場合は [`TransportOption`](/autd3-sdk/api/basics/transport-option/) の `sync_on_open` を `false` にして開き, `Clear` を送ってから開き直す.
