[`Client`](/autd3-sdk/api/basics/client/) の `device_status` を使うことでデバイスとの通信が正常に動いているかどうかを監視できる.

## 状態の取得

`device_status` は, 呼び出した時点の各デバイスの状態 `DeviceStatus` の配列を返す.

`DeviceStatus` は以下を持つ.

- `state`: デバイスの状態 (`DeviceState`).
- `ptp_locked`: PTP がロックしているか.
- `failsafe_active`: フェイルセーフで出力を止めていて, まだ解除されていないか

全デバイスが `Ready` か, といった集約は返り値から作る (下の例を参照).
`ptp_locked` と `failsafe_active` はデバイスからの最後の返信の値である.
`Client` を閉じた後に呼ぶとエラー (`Closed`. 通信エラーで閉じた場合は `Network`, デバイスの途絶で閉じた場合は `DeviceLost`) になる.

`DeviceState`の意味は以下の通り. 

| 状態     | 意味                                                                     |
| -------- | ------------------------------------------------------------------------ |
| `Ready`   | 返信があり, 時刻が同期されている                                        |
| `Syncing` | 返信はあるが, 時刻を合わせている途中                                    |

1 台でも返信が `lost_timeout` の間無ければ (途絶), `Client` はその時点で閉じ, 以後の送信・読み出し・`device_status` はすべて `DeviceLost` (途絶したデバイスの番号を持つ) で失敗する.
途中の 1 台が途絶すると, その機体より先の機体にも届かなくなる.
途絶からの自動復帰はしない.
そのため, 途絶した場合は `Client::open` で開き直すしかない.
