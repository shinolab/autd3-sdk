デバイスの状態は返信に載ってくる. [`Client`](/autd3-sdk/api/basics/client/) の `read_state` (全デバイスへ生存確認を送り, 返信を集める) が返す `Response` の `device_status` を見ることで, デバイスとの通信が正常に動いているかどうかを監視できる.
`Client` 自身は状態を保持しない.

## 状態の取得

`Response` の `device_status` は, その返信の時点の各デバイスの状態 `DeviceStatus` の配列を返す.

`DeviceStatus` は以下を持つ.

- `state`: デバイスの状態 (`DeviceState`).
- `ptp_locked`: PTP がロックしているか.
- `failsafe_active`: フェイルセーフで出力を止めていて, まだ解除されていないか

全デバイスが `Ready` か, といった集約は返り値から作る (下の例を参照).
`ptp_locked` と `failsafe_active` はその返信の値である.

`DeviceState`の意味は以下の通り. 

| 状態     | 意味                                                                     |
| -------- | ------------------------------------------------------------------------ |
| `Ready`   | 返信があり, 時刻が同期されている                                        |
| `Syncing` | 返信はあるが, 時刻を合わせている途中                                    |

返信が来ないデバイス (途絶) は, `read_state` が返らないことで分かる.
`Client` は途絶を判定しないので, 待つ時間の上限 (Rust は `tokio::time::timeout`, Python は `asyncio.wait_for`, C# は `CancellationToken`) と, 途絶したときに送信を止めるか開き直すかはユーザーが決める.
途中の 1 台が途絶すると, その機体より先の機体にも届かなくなる.
途絶からの自動復帰はしない. 途絶した後も送り続けると, 全台への送信が失敗するようになることがあるので, 送信を止めて `Client::open` で開き直す.
未割り当て・別 ID の返信 (再起動したデバイスなど) は `DeviceLost` (そのデバイスの番号を持つ) エラーになる.
