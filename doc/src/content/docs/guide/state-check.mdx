## 状態の取得

`StateChecker::check` は, 呼び出した時点の状態 `DeviceStatus` を返す.
`DeviceStatus` は以下を持つ.

- `devices`: デバイスごとの状態 (`DeviceState`).
- `all_ready`: 全デバイスが `Ready` 状態か.
- `any_lost`: いずれかのデバイスが `Lost` 状態か.

状態の意味は以下の通り. 

| 状態     | 意味                                                                     |
| -------- | ------------------------------------------------------------------------ |
| `Ready`   | 返信があり, デバイスの時刻が合っていて, 同期パルスが動いている          |
| `Syncing` | 返信はあるが, 時刻を合わせている途中か, 同期パルスがまだ動いていない    |
| `Lost`    | 返信が一定時間無い                                      |

途中の 1 台が`Lost`すると, その機体より先の機体も全て `Lost` になる.
`Lost` のデバイスは自動では復帰しない ([Lost からの復帰](#lost-からの復帰) 参照).

## Lost からの復帰

`Client::recover` を呼ぶと, `Lost` のデバイスを 1 回だけ探し, 応答が戻ったデバイスを復帰させる.
復帰したデバイスがあれば `Reset` を送ってデバイスとの足並みを揃え直してから, 復帰したデバイスを返す.
戻り値は復帰したデバイスの集合 `DeviceMask` である. `recovered[i]` でデバイス `i` が復帰したかを `bool` で返す.

対象はケーブルの抜き差しなどで通信が途絶えただけのデバイスで, 電源を入れ直したデバイスは復帰しない (`Client::open` で開き直す).
復帰したデバイスの延べ数は `BusStats` の `recoveries` で読める.

以下は, `check` で `Lost` を見つけたら `recover` を呼び, 復帰したデバイスへ `Synchronize` を, 続いて `ReleaseFailsafe` を送る例.

復帰の際には以下の点に注意されたい.

- `recover` は `Synchronize` も `ReleaseFailsafe` も送らない. `Lost` の間はデバイスに何も届かないので, フェイルセーフ ([SetCpuConfig](/autd3-sdk/api/command/cpu-config/) 参照) を有効にしていると出力は止まっている可能性がある.
  - 出力の位相を揃え直すには [`Synchronize`](/autd3-sdk/api/command/clear/#synchronize--nop) を送る
  - 止まった出力を再開させるには [`ReleaseFailsafe`](/autd3-sdk/api/command/release-failsafe/) を送る. `ReleaseFailsafe` はフェイルセーフで止まっていないデバイスには何もしないので, 全デバイスへ送ってよい.
- 復帰したデバイスが `Syncing` の場合は, `check` で `Ready` になるのを待ってから `Synchronize` を送る.
- `recover` の間, 他の送信は待たされる. また, `Reset` の時点で返信待ちのフレームは `Timeout` で失敗する.
