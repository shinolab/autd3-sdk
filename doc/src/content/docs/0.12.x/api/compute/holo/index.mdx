Holo は複数の焦点 (制御点) を同時に生成するための Pattern 計算群.
各振動子の位相・振幅を最適化し, 指定した複数点で目標音圧が得られるようにする.

<Install rust="autd3-rs-pattern-holo" python="autd3-pattern-holo" csharp="AUTD3.Pattern.Holo" />

提供するアルゴリズムは以下の通り.

* [Naive](/autd3-sdk/0.12.x/api/compute/holo/naive/) — 単一ステップの逆伝搬
* [GS](/autd3-sdk/0.12.x/api/compute/holo/gs/) — Gerchberg-Saxton 法
* [GS-PAT](/autd3-sdk/0.12.x/api/compute/holo/gspat/) — GS-PAT 法
* [Greedy](/autd3-sdk/0.12.x/api/compute/holo/greedy/) — 位相を貪欲に決定する組合せ最適化

## 共通要素

### AmplitudeTarget

焦点を表す構造体. 位置 `point` と目標振幅 `amplitude` を持つ (Python はプロパティ `point` / `amplitude`, C# は `Point` / `Amplitude`).

### 振幅単位 `Pa` / `kPa` / `dB`

目標振幅 `Amplitude` は, `f32` に振幅単位を掛けて構築する.
値は `pascal()` (Pa) と `spl()` (dB) で読む (Python はプロパティ `pascal` / `spl`, C# は `Pascal` / `Spl`).
`Amplitude` はスカラ倍 (`* f32` / `f32 *`)・除算 (`/ f32`)・大小比較ができる (Python / C# も同じ).

### IntensityConstraint

最適化で得られた振幅は, そのままでは振動子では出力できない強度の可能性がある.
そこで, 最適化で得た振幅を, 出力する振動子強度へ変換するための制約を指定する.

|                                 |                                                |
|---------------------------------|------------------------------------------------|
| `Normalize`                     | 最大値で正規化する                             |
| `Multiply(f32)`                 | 正規化後に係数を掛けてクランプする             |
| `Uniform(Intensity)`            | 全振動子を一定強度にする                       |
| `Clamp(Intensity, Intensity)`   | 振幅を指定範囲にクランプする                   |

各 Option の `constraint` フィールドで指定する. デフォルトは `naive` / `gs` / `gspat` とも `Clamp(Intensity::MIN, Intensity::MAX)`.
`greedy` は振幅を最適化しないので `constraint` を持たず, 振幅は入力として与える.

### エラー

各関数の失敗は, Rust では `HoloError`, Python では `HoloError` (`autd3_core.Autd3Error` のサブクラスで `code` は `INVALID_ARGUMENT`), C# では `Autd3Exception` (`Code` は `InvalidArgument`) になる.
焦点が空のとき, 出力バッファの台数が `geometry` と合わないとき, `mask` の形が `geometry` と合わないときなどに失敗する.

### Directivity

振動子の指向性モデル.
無指向性の `Sphere` (デフォルト) , または, 実機指向性の `T4010A1` から選べる.
各 Option の `directivity` フィールドで指定する.

### TransducerMask

最適化に含める振動子を選択する.
各 Option の `mask` フィールドで指定する (デフォルトは `AllEnabled`).

* `TransducerMask::AllEnabled` — 全振動子を使う (デフォルト).
* `TransducerMask::Masked(&[Vec<bool>])` — 各振動子ごとに有効/無効を指定する.

Python では `TransducerMask.AllEnabled` / `TransducerMask.masked(rows)`, C# では `TransducerMask.AllEnabled` / `TransducerMask.Masked(bool[][])` と書く.
Python の `mask` に `None` は渡せない (`TypeError`). [`TransducerGroups.mask(key)`](/autd3-sdk/0.12.x/api/compute/pattern/group/) がどの振動子にも割り当てられていないキーで返す `None` が, 全振動子の指定として黙って通ることはない.

### LinAlgBackend (NalgebraBackend)

`naive` / `gs` / `gspat` は線形代数演算を `LinAlgBackend` トレイトに委譲する.
標準実装としてCPUで計算する `NalgebraBackend` を用いる.
バックエンドは各関数の第 1 引数で渡す.

`greedy` は行列演算を使わないためバックエンドを取らない.

Python / C# は `NalgebraBackend` に固定しており, バックエンドの引数を取らない.

### GPU Backend (WgpuBackend)

GPUで計算するバックエンドとして `WgpuBackend` を用意している (Rust のみ).

### バッチ API

`naive` / `gs` / `gspat` には, 独立した複数の問題をまとめて解く `naive_batch` / `gs_batch` / `gspat_batch` がある.

<CodeTabs rust={"let problems = 64;\nlet foci: Vec<AmplitudeTarget> = (0..problems)\n    .map(|i| AmplitudeTarget {\n        point: center + offset(i as f32 * 0.5 * mm, 0.0 * mm, 0.0 * mm),\n        amplitude: 5e3 * Pa,\n    })\n    .collect();\n\nlet mut phases = vec![geometry.phase_buffer(); problems];\nlet mut intensities = vec![geometry.intensity_buffer(); problems];\ngs_batch(\n    &NalgebraBackend,\n    &geometry,\n    &foci,\n    wavelength,\n    &option,\n    &mut phases,\n    &mut intensities,\n)?;"} python={"problems = 64\nfoci = [\n    AmplitudeTarget(\n        center + offset(i * 0.5 * mm, 0.0 * mm, 0.0 * mm),\n        5e3 * Pa,\n    )\n    for i in range(problems)\n]\n\nphases = [geometry.phase_buffer() for _ in range(problems)]\nintensities = [geometry.intensity_buffer() for _ in range(problems)]\ngs_batch(\n    geometry,\n    foci,\n    wavelength,\n    option,\n    phases,\n    intensities,\n)"} csharp={"var problems = 64;\nvar foci = Enumerable.Range(0, problems)\n    .Select(i => new AmplitudeTarget(center + Offset(i * 0.5f * mm, 0.0f * mm, 0.0f * mm), 5e3f * Pa))\n    .ToArray();\n\nvar phases = Enumerable.Range(0, problems).Select(_ => geometry.PhaseBuffer()).ToArray();\nvar intensities = Enumerable.Range(0, problems).Select(_ => geometry.IntensityBuffer()).ToArray();\nHolo.GsBatch(geometry, foci, wavelength, option, phases, intensities);"} />

問題数は `phases` / `intensities` の長さで決まる (両者の長さは揃える).
焦点は 問題数 × 各問題あたりの焦点数 の長さのスライスを渡す.
全問題は焦点数が揃っている必要があり, 問題数で割り切れなければエラーになる.

バッチ API で計算速度に利があるのは GPU バックエンドだけである. CPU バックエンド (Python / C# の `NalgebraBackend` を含む) は問題を 1 つずつ順に解くので, 1 問題ずつ関数を呼ぶのと速度は変わらない.
