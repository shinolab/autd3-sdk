The devices have a failsafe feature that stops their output by themselves when communication with the host is lost or when they lose the PTP lock.
Both are disabled by default and can be enabled with [SetCpuConfig](/autd3-sdk/en/api/command/cpu-config/).

## Communication-loss failsafe and liveness check

If `failsafe_timeout` is set, a device stops its output when communication from the host has been cut off for that long.
The default is `None` (disabled), and the devices do not stop the ultrasound even if communication is cut off by a host crash or a broken cable.

While there is nothing to send, `Client` sends nothing to the devices by itself.
Therefore, when `failsafe_timeout` is set, you need to call [`send_heartbeat()`](/autd3-sdk/en/api/basics/client/#api) periodically while you wait with the output kept on.
`send_heartbeat()` must be called at a period sufficiently shorter than `failsafe_timeout`.

An output stopped by the failsafe does not come back automatically.
Whether it is stopped can be checked with `failsafe_active` of the `DeviceStatus` that `device_status()` returns, and sending [`ReleaseFailsafe`](/autd3-sdk/en/api/command/release-failsafe/) resumes it ([Clear](/autd3-sdk/en/api/command/clear/) also works, but it resets every state).

## Detecting and releasing the PTP failsafe

If `ptp_unlock_failsafe_timeout` is set with [SetCpuConfig](/autd3-sdk/en/api/command/cpu-config/), a device that has stayed without the PTP lock for the given time stops its output.
