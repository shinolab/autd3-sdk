`device_status` of the [`Client`](/autd3-sdk/en/api/basics/client/) lets you monitor whether the communication with the devices is working correctly.

## Obtaining the State

`device_status` returns an array of the state `DeviceStatus` of each device at the time of the call.

`DeviceStatus` holds the following.

- `state`: the state of the device (`DeviceState`).
- `ptp_locked`: whether its PTP is locked.
- `failsafe_active`: whether it stopped its output by the failsafe and has not been released yet

Aggregates such as whether every device is `Ready` are built from the returned values (see the example below).
`ptp_locked` and `failsafe_active` are taken from the last reply of each device.
Calling it after the `Client` is closed returns an error (`Closed`, `Network` if it closed on a communication error, or `DeviceLost` if it closed because a device was lost).

The meaning of each `DeviceState` is as follows.

| State     | Meaning                                                    |
| --------- | ---------------------------------------------------------- |
| `Ready`   | The device replies and its time is synchronized            |
| `Syncing` | The device replies, but its time is still being synchronized |

If even one device does not reply for `lost_timeout` (the device is lost), the `Client` closes at that point, and every later send, read and `device_status` fails with `DeviceLost` (which holds the number of the lost device).
When a device in the middle of the chain is lost, the devices beyond it are no longer reached either.
There is no automatic recovery.
Therefore, once a device is lost, the only way is to reopen the client with `Client::open`.
