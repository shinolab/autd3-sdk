## Obtaining the State

`StateChecker::check` returns the state `DeviceStatus` at the time of the call.
`DeviceStatus` holds the following.

- `devices`: the state of each device (`DeviceState`).
- `all_ready`: whether all devices are in the `Ready` state.
- `any_lost`: whether any device is in the `Lost` state.
- `ptp_locked`: the set of devices whose PTP is locked (`DeviceMask`).
- `ptp_failsafe`: the set of devices that stopped their output because they lost the PTP lock and have not been released yet (`DeviceMask`).
- `any_ptp_failsafe`: whether `ptp_failsafe` is not empty.

`ptp_locked` and `ptp_failsafe` are taken from the last reply of each device, and a `Lost` device is in neither of them.

The meaning of each state is as follows.

| State     | Meaning                                                                              |
| --------- | ------------------------------------------------------------------------------------ |
| `Ready`   | The device replies, its time is synchronized, and its sync pulse is running           |
| `Syncing` | The device replies, but its time is still being synchronized or its sync pulse is not running yet |
| `Lost`    | No reply for a certain period of time                                                 |

When a device in the middle of the chain becomes `Lost`, every device beyond it also becomes `Lost`.
A `Lost` device does not come back while the `Client` is open. It stays `Lost` even if the communication comes back, for example after replugging a cable, so `close` the client and reopen it with `Client::open`.

While nothing is sent, a device does not become `Lost` even if the communication with it is cut off.

## Detecting and Releasing the PTP Failsafe

If `ptp_unlock_failsafe_timeout` is set with [SetCpuConfig](/autd3-sdk/en/api/command/cpu-config/), a device that stays without the PTP lock for that time stops its output.
Such a device enters `ptp_failsafe` and stays there until it is released with [`ReleaseFailsafe`](/autd3-sdk/en/api/command/release-failsafe/) or [Clear](/autd3-sdk/en/api/command/clear/) (relocking does not release it automatically).

The following is an example that sends `ReleaseFailsafe` to the devices in `ptp_failsafe` that have relocked.
`send_heartbeat()` returns without waiting for the replies, so wait until they arrive before calling `check` (calling it right away returns the values of the previous replies).
The PTP failsafe is not released by reopening the `Client`, but right after opening, `ptp_failsafe` is empty until the first replies arrive.

Sending `ReleaseFailsafe` to a device that is still without the lock returns an error, and its output stays stopped. Wait until it enters `ptp_locked` before sending.
Output stopped for a reason other than PTP, such as a lost connection to the host, does not appear in `ptp_failsafe` (check it with `is_failsafe_active()` of `read_fpga_state()`).
