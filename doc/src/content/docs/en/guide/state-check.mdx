## Obtaining the State

`StateChecker::check` returns the state `DeviceStatus` at the time of the call.
`DeviceStatus` holds the following.

- `devices`: the state of each device (`DeviceState`).
- `all_ready`: whether all devices are in the `Ready` state.
- `any_lost`: whether any device is in the `Lost` state.

The meaning of each state is as follows.

| State     | Meaning                                                                              |
| --------- | ------------------------------------------------------------------------------------ |
| `Ready`   | The device replies, its time is synchronized, and its sync pulse is running           |
| `Syncing` | The device replies, but its time is still being synchronized or its sync pulse is not running yet |
| `Lost`    | No reply for a certain period of time                                                 |

When a device in the middle of the chain becomes `Lost`, every device beyond it also becomes `Lost`.
A `Lost` device is never recovered automatically (see [Recovery from Lost](#recovery-from-lost)).

While nothing is sent, a device does not become `Lost` even if the communication with it is cut off.

## Recovery from Lost

`Client::recover` looks for the `Lost` devices once and recovers the devices that answer again.
If any device came back, it sends `Reset` to bring the devices back in step, and then returns the recovered devices.
The return value is the set of recovered devices, a `DeviceMask`. `recovered[i]` returns a `bool` telling whether device `i` came back (`false` for an out-of-range index). 
If no device is `Lost`, it sends nothing and returns immediately.

Only a device whose communication was cut off, for example by an unplugged cable, is recovered; a power-cycled device is not (reopen the client with `Client::open`).
The total number of recovered devices can be read from `recoveries` of `BusStats`.

Note the following when a device is recovered.

- `recover` sends neither `Synchronize` nor `ReleaseFailsafe`. Nothing reaches a device while it is `Lost`, so its output might have been stopped by the failsafe if the failsafe is enabled (see [SetCpuConfig](/autd3-sdk/en/api/command/cpu-config/)).
  - Send [`Synchronize`](/autd3-sdk/en/api/command/synchronize/) yourself to realign the output phase
  - Send [`ReleaseFailsafe`](/autd3-sdk/en/api/command/release-failsafe/) to resume the stopped output. `ReleaseFailsafe` does nothing to a device that is not stopped by the failsafe, so it can be sent to all devices.
- If a recovered device is `Syncing`, wait with `check` until it becomes `Ready` before sending `Synchronize`.
- Other sends wait while `recover` runs. Frames still waiting for a reply when the `Reset` is sent fail with `Timeout`.
