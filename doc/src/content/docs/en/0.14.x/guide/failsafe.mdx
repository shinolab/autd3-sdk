The devices have a failsafe feature that stops their output by themselves when communication with the host is lost or when they lose the PTP lock.
Both are disabled by default and can be enabled with [SetCpuConfig](/autd3-sdk/en/0.14.x/api/command/cpu-config/).

## Communication-loss failsafe and liveness check

If `failsafe_timeout` is set, a device stops its output when communication from the host has been cut off for that long.
The default is `None` (disabled), and the devices do not stop the ultrasound even if communication is cut off by a host crash or a broken cable.

By default, `Client` sends nothing to the devices by itself while there is nothing to send.
Therefore, when `failsafe_timeout` is set, set `heartbeat_interval` in [`TransportOption`](/autd3-sdk/en/0.14.x/api/basics/transport-option/) so that liveness checks are sent periodically.
The interval must be sufficiently shorter than `failsafe_timeout` (aim for less than half).

The following is an example that sets `failsafe_timeout` to 100 ms and sends a liveness check every 10 ms.

<CodeTabs rust={"let option = TransportOption {\n    heartbeat_interval: Some(Duration::from_millis(10)),\n    ..Default::default()\n};\nlet mut client = Client::open(&geometry, &option).await?;\n\nclient\n    .send(SetCpuConfig::new(CpuConfig {\n        failsafe_timeout: Some(Duration::from_millis(100)),\n        ..Default::default()\n    }))\n    .await?;"} python={"client = Client.open(geometry, TransportOption(heartbeat_interval=Duration.from_millis(10)))\n\nawait client.send(SetCpuConfig(CpuConfig(failsafe_timeout=Duration.from_millis(100))))"} csharp={"var client = Client.Open(geometry, new TransportOption { HeartbeatInterval = TimeSpan.FromMilliseconds(10) });\n\nawait client.SendAsync(new SetCpuConfig(new CpuConfig { FailsafeTimeout = TimeSpan.FromMilliseconds(100) }));"} />

An output stopped by the failsafe does not come back automatically.
Whether it is stopped can be checked with `failsafe_active` of the `DeviceStatus` that `device_status()` of a reply (`Response`) returns, and sending [`ReleaseFailsafe`](/autd3-sdk/en/0.14.x/api/command/release-failsafe/) resumes it ([Clear](/autd3-sdk/en/0.14.x/api/command/clear/) also works, but it resets every state).

## Detecting and releasing the PTP failsafe

If `ptp_unlock_failsafe_timeout` is set with [SetCpuConfig](/autd3-sdk/en/0.14.x/api/command/cpu-config/), a device that has stayed without the PTP lock for the given time stops its output.

The following is an example that sends `ReleaseFailsafe` to the devices that have `failsafe_active` set and have relocked (`ptp_locked` is set).

<CodeTabs rust={"let status = client.read_state().await?.device_status();\nlet releasable = |s: &DeviceStatus| s.failsafe_active && s.ptp_locked;\nif status.iter().any(releasable) {\n    client\n        .send(each(|device| {\n            releasable(&status[device.idx()]).then_some(ReleaseFailsafe)\n        }))\n        .await?;\n}"} python={"status = (await client.read_state()).device_status()\n\ndef releasable(s: DeviceStatus) -> bool:\n    return s.failsafe_active and s.ptp_locked\n\nif any(releasable(s) for s in status):\n    await client.send(each(lambda device: ReleaseFailsafe() if releasable(status[device.idx()]) else None))"} csharp={"var status = (await client.ReadStateAsync()).DeviceStatus();\nstatic bool Releasable(DeviceStatus s) => s.FailsafeActive && s.PtpLocked;\nif (status.Any(Releasable))\n{\n    await client.SendAsync(Command.Each(device => Releasable(status[device.Idx]) ? new ReleaseFailsafe() : null));\n}"} />

Sending `ReleaseFailsafe` to a device that is still without the lock returns an error, and its output stays stopped.
