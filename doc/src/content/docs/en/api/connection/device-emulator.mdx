`UdpEmulator` emulates a chain of AUTD3 devices on the host (`::1`).
Without any hardware, you can open a `Client` and send commands over the same UDP path as with real devices.
The data sent to each device is processed by the actual CPU firmware logic and an FPGA emulator.
Use it for tests, samples, and trying things out.

<CodeTabs rust={sample} python={pySample} csharp={csSample} />

- `UdpEmulator::spawn(n)` (`UdpEmulator(n)` in Python, `new UdpEmulator(n)` in C#) starts `n` devices
- `option()` returns a [`TransportOption`](/autd3-sdk/en/api/connection/) pointing at the emulator. Pass it to `Client::open`
- `reboot(i)` emulates a reboot of the `i`-th device. It and every device behind it stop answering, and the [state check](/autd3-sdk/en/guide/state-check/) reports them as `Lost`
- In Rust, `with_device(i, ..)` observes the firmware and FPGA state of the `i`-th device
- In Rust, enable the `emulator` feature of `autd3-rs`. Python and C# include it in the main package

The emulator does not reproduce the timing behavior of the hardware, such as the accuracy of the sync pulse.
To see the resulting sound field, use the [Simulator](/autd3-sdk/en/guide/simulator/).
