:::note
`Controller` / `Driver` are provided in Rust only.
:::

`Controller` and `Driver` are the parts that let you drive the internals of [`Client`](/autd3-sdk/en/api/basics/client/) yourself.

`Client` owns one I/O thread that receives the replies and sends the liveness checks.
Use `Controller` / `Driver` when you want to run the send/receive loop on your own thread or the like instead of that thread.

## Open

`Controller::open` returns a tuple of `Controller` and `Driver`.
It takes the same arguments as `Client::open`.

<CodeTabs rust={excerpt(sample, "run")} />

Unlike `Client::open`, `Controller::open` does not initialize the devices (handshake, firmware version check, `Clear`, `Synchronize`).
Start driving the `Driver` first, then call `controller.initialize().await`, and send commands only after it completes.
`initialize` waits for replies, so it does not complete if called before the `Driver` is driven.

## Driver

`Driver` has the following methods.

| Method            | Return value                     | Description                                                              |
| ----------------- | -------------------------------- | ------------------------------------------------------------------------ |
| `run(self)`       | `Result<(), Error>`              | Repeats `poll` and `wait` until the `Controller` is closed. Blocking.    |
| `poll(&mut self)` | `Result<Option<Instant>, Error>` | Processes the replies that have arrived and the work that is due, and returns the deadline for the next call. Non-blocking. |
| `wait(&mut self, deadline)` | `Result<(), Error>`    | Blocks the thread until a reply arrives or `deadline` is reached         |

### poll / wait

`run` is the same as the following loop.
Call `poll` and `wait` directly when you want to put your own work inside the loop.

<CodeTabs rust={excerpt(sample, "poll")} />

The return value of `poll` means the following.

- `Ok(Some(deadline))`: the deadline by which `poll` should be called next. Call it earlier if a reply arrives before the deadline. `wait` waits for either of the two.
- `Ok(None)`: the `Controller` has been closed (`close` or drop). Leave the loop.
- `Err(..)`: a communication error. The commands being sent and all later sends fail with an error of the same cause.

## Notes

- If the `Controller` is dropped first, `poll` of the `Driver` returns `Ok(None)`. The output of the devices is not stopped in this case, so call `close` when you finish.
- If the `Driver` is dropped first, the commands being sent and all later sends fail with `Error::Closed`.
- The async methods of `Controller` never complete unless the `Driver` is polled.
