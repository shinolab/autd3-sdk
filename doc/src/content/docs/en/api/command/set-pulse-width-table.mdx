`SetPulseWidthTable` is a command that sets the conversion table from intensity (0–255) to the PWM pulse width.

## API

<CodeTabs rust={excerpt(sample, "api")} python={excerpt(pySample, "api")} csharp={excerpt(csSample, "api")} />

| Field   | Type                    | Description                                              |
| ------- | ----------------------- | ------------------------------------------------------- |
| `table` | `[PulseWidth; PWE_TABLE_SIZE]` | Pulse width per intensity index (0–255) (256 elements) |

A `PulseWidth` is made with `PulseWidth::new(u16)` (a pulse width in 512 steps per period) or `PulseWidth::from_duty(f32)` (a duty ratio), and its value is read with `pulse_width()`.
The range is validated at construction: `new` returns `Err(PulseWidthError)` outside `[0, 512)`, and `from_duty` outside `[0, 1)`.
A `PulseWidth` that was made is always in range, so a table never fails at encode time.
Python is the same (`PulseWidth(raw)` / `PulseWidth.from_duty(duty)` / `pulse_width()`; an out-of-range value raises `Autd3Error` (`INVALID_ARGUMENT`) at construction).
C# makes it with `new PulseWidth(ushort)` / `PulseWidth.FromDuty(float)` and reads the value with `Value` (not `PulseWidth`, because a member cannot have the same name as its type). An out-of-range value throws `Autd3Exception` (`InvalidArgument`) at construction.

The default command sets an arcsin-shaped table.
This is a table that makes the output sound pressure (theoretically) linear with respect to intensity, and it is the same table the device holds at boot.
