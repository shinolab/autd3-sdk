`WriteFociBuffer` is a low-level command that writes a focal point sequence for Foci STM into a bank.

## API

<CodeTabs rust={excerpt(sample, "write")} python={excerpt(pySample, "write")} csharp={excerpt(csSample, "write")} />

| Field          | Type                  | Description                        |
| -------------- | --------------------- | ---------------------------------- |
| `bank`         | `PatternBank`         | Destination bank                   |
| `start_index` | `usize`               | Start index for writing within the bank |
| `points`       | `&[ControlPoints]`    | Sequence of focal point samples    |

`ControlPoints` is one sample holding a sequence of focal points (`ControlPoint`) and an amplitude. Every sample must have the same number of foci.
For details see [FociStm](/autd3-sdk/en/api/command/foci-stm/#controlpoint--controlpoints).

`WriteFociBuffer` is sent as a single frame and writes only what fits in one frame.
The limit (in `ControlPoints`) depends on the number of foci: `WriteFociBuffer::max_len(num_foci)` in Rust, `WriteFociBuffer.max_len(num_foci)` in Python, and `WriteFociBuffer.MaxLen(numFoci)` in C#; exceeding it is an error when sending.
Split a longer sequence and send it with `start_index` advanced by the limit (the high-level [FociStm](/autd3-sdk/en/api/command/foci-stm/) does this split automatically).
Since it is a single-frame command, [each](/autd3-sdk/en/api/basics/client/#each) can assign a different sequence to each device.
