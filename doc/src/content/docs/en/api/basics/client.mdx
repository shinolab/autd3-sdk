`Client` is the central object that sends commands and reads state.
The basic and command APIs, including `Client`, are provided by the main package.
The destination (real devices, the [device emulator](/autd3-sdk/en/api/connection/device-emulator/), or the Simulator) is given by [`TransportOption`](/autd3-sdk/en/api/connection/).

Before opening a `Client`, open a [`Driver`](/autd3-sdk/en/api/basics/driver/) and start running it.
Pass the `Connector` returned by `Driver::open` to `Client::open`.
The library spawns no thread for sending and receiving, so awaiting `Client::open` without running the `Driver` never returns.

## ClientConfig

<CodeTabs rust={excerpt(open, "config")} python={excerpt(pyOpen, "config")} csharp={excerpt(csOpen, "config")} />

| Field                  | Type                     | Default | Description                                                |
| ---------------------- | ------------------------ | ------- | ---------------------------------------------------------- |
| `ack_timeout`          | `Duration`               | 10 ms   | Response-wait timeout; the frames are sent again after it  |
| `max_inflight`         | `NonZeroUsize`           | `7`     | Frames that may be sent without waiting for a reply (the default is the capacity of the device receive queue) |
| `max_resync_rounds`    | `NonZeroU32`             | `8`     | Maximum number of rounds to attempt resynchronization      |
| `low_latency`          | `bool`                   | `false` | Low-latency mode                                           |
| `validate_state`       | `bool`                   | `true`  | Enable pre-send validation                                 |
| `require_supported_firmware` | `bool`             | `false` | Check the firmware series on open (Rust only) |

`max_inflight` errors if it exceeds `MAX_INFLIGHT (127)`.
The device receive queue holds 7 frames, so a value above the default does not speed anything up (the overflowing frames are sent again).

Enabling `low_latency` bypasses the receive buffer inside the firmware, improving latency.
However, this may make operation unstable.
