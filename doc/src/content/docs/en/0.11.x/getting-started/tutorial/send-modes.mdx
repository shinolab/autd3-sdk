A command is encoded into one or more `Frame`s and then sent.
There are two ways to send, with a trade-off between reliability and throughput.

Below, the two send methods are compared using an example that moves the focal point along a circle.
The focal positions to move to are prepared in advance as `targets`.

<CodeTabs rust={"// Prepare 1000 focus points along a circle 150 mm above the array center.\nlet center = geometry.center() + offset(0.0 * mm, 0.0 * mm, 150.0 * mm);\nlet targets: Vec<Point3<f32>> = (0..NUM_POINTS)\n    .map(|i| {\n        let theta = 2.0 * PI * i as f32 / NUM_POINTS as f32;\n        center\n            + offset(\n                RADIUS_MM * theta.cos() * mm,\n                RADIUS_MM * theta.sin() * mm,\n                0.0 * mm,\n            )\n    })\n    .collect();"} python={"# Prepare 1000 focus points along a circle 150 mm above the array center.\ncenter = geometry.center() + np.array([0.0, 0.0, 150.0])\ntargets = [\n    center\n    + np.array(\n        [\n            RADIUS_MM * math.cos(2.0 * math.pi * i / NUM_POINTS),\n            RADIUS_MM * math.sin(2.0 * math.pi * i / NUM_POINTS),\n            0.0,\n        ]\n    )\n    for i in range(NUM_POINTS)\n]"} csharp={"// Prepare 1000 focus points along a circle 150 mm above the array center.\nvar center = geometry.Center + new Vector3(0.0f, 0.0f, 150.0f);\nvar targets = new Vector3[NumPoints];\nfor (var i = 0; i < NumPoints; i++)\n{\n    var theta = 2.0f * MathF.PI * i / NumPoints;\n    targets[i] = center + new Vector3(RadiusMm * MathF.Cos(theta), RadiusMm * MathF.Sin(theta), 0.0f);\n}"} />

## stop-and-wait

A method that waits for a response after each frame before sending the next.
It uses `send`.
Because it proceeds to the next frame only after confirming that each update has been reliably applied, it is reliable, but throughput is low because a round-trip latency is incurred on every frame.

<CodeTabs rust={"let mut phases = geometry.phase_buffer();\nfor &target in targets {\n    autd3_rs_pattern::focus(\n        geometry,\n        target,\n        wavelength,\n        &mut phases,\n    );\n    client.send(Pattern::new(&phases, Intensity::MAX)).await?;\n}"} python={"phases = geometry.phase_buffer()\nfor target in targets:\n    pattern.focus(\n        geometry,\n        target,\n        wavelength,\n        phases,\n    )\n    await client.send(Pattern(phases, Intensity.MAX))"} csharp={"var phases = geometry.PhaseBuffer();\nforeach (var target in targets)\n{\n    Pattern.Focus(\n        geometry,\n        target,\n        wavelength,\n        phases\n    );\n    await client.SendAsync(new Pattern(phases, Intensity.Max));\n}"} />

## streaming

A method that sends one frame after another without waiting for responses, and collects the responses together later.
Because it does not wait for a response on every frame, throughput is high.

As in the example below, convert the command into frames with `Frames::encode_into` and then send them one frame at a time with `send_frame`.
`send_frame` returns a `ResponseFuture` at the point the frame is enqueued, and awaiting that `ResponseFuture` yields the device's response (`Response`).
`Response` can be validated for device errors with `check`.
The maximum size of the send queue is `MAX_INFLIGHT (7)`.
`ResponseFuture`s are held in FIFO order, and when the queue is full the oldest response is collected.

<CodeTabs rust={"let mut phases = geometry.phase_buffer();\nlet mut frames = Frames::default();\nlet mut pending: VecDeque<ResponseFuture> = VecDeque::with_capacity(MAX_INFLIGHT);\nfor &target in targets {\n    autd3_rs_pattern::focus(\n        geometry,\n        target,\n        wavelength,\n        &mut phases,\n    );\n    frames.encode_into(geometry, Pattern::new(&phases, Intensity::MAX))?;\n    for frame in &frames {\n        if pending.len() >= MAX_INFLIGHT {\n            pending.pop_front().expect(\"non-empty\").await?.check()?;\n        }\n        pending.push_back(client.send_frame(frame).await?);\n    }\n}\n// Drain the remaining responses.\nwhile let Some(response) = pending.pop_front() {\n    response.await?.check()?;\n}"} python={"phases = geometry.phase_buffer()\nframes = Frames()\npending = collections.deque()\nfor target in targets:\n    pattern.focus(\n        geometry,\n        target,\n        wavelength,\n        phases,\n    )\n    frames.encode_into(geometry, Pattern(phases, Intensity.MAX))\n    for frame in frames:\n        if len(pending) >= MAX_INFLIGHT:\n            (await pending.popleft()).check()\n        pending.append(await client.send_frame(frame))\n# Drain the remaining responses.\nwhile pending:\n    (await pending.popleft()).check()"} csharp={"var phases = geometry.PhaseBuffer();\nusing var frames = new Frames();\nvar pending = new Queue<ResponseFuture>();\nforeach (var target in targets)\n{\n    Pattern.Focus(\n        geometry,\n        target,\n        wavelength,\n        phases\n    );\n    frames.EncodeInto(geometry, new Pattern(phases, Intensity.Max));\n    foreach (var frame in frames)\n    {\n        if (pending.Count >= Client.MaxInflight)\n        {\n            (await pending.Dequeue()).Check();\n        }\n        pending.Enqueue(await client.SendFrameAsync(frame));\n    }\n}\n// Drain the remaining responses.\nwhile (pending.Count > 0)\n{\n    (await pending.Dequeue()).Check();\n}"} />

Note that `send_streaming` can also be used when only a single command is sent.

For commands that must be applied reliably one at a time, such as initialization and configuration, use stop-and-wait.
For situations where throughput matters, such as updating the focal point at high frequency, use streaming.
For details on `send` / `send_streaming` / `send_frame`, refer to [Sending](/autd3-sdk/en/0.11.x/api/basics/client/).
