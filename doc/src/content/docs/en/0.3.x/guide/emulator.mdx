`Emulator` is a tool that records AUTD3 drive data without real hardware and computes the sound field offline from it.
It is provided as a package separate from the main library (no package is provided for C#).

<Install rust="autd3-rs-emulator" python="autd3-emulator" />

## Recording

By passing a `Geometry` to `Emulator::new`, sending data inside `record`, and advancing time with `tick`, a `Record` with the sent data recorded is obtained.

<CodeTabs rust={"let emulator = Emulator::new(geometry);\nlet record = emulator.record(async move |r| {\n    let mut builder = r.datagram_builder();\n    builder.push(Pattern::new(&patterns));\n    let datagrams = builder.build()?;\n    for frame in &datagrams {\n        r.send_checked(frame).await?;\n    }\n    r.tick(Duration::from_millis(1))?;\n    Ok(())\n})?;"} python={"emulator = Emulator(geometry)\n\n\ndef record_fn(r: Recorder) -> None:\n    builder = r.datagram_builder()\n    builder.push(Pattern(patterns))\n    for frame in builder.build():\n        r.send_checked(frame)\n    r.tick(Duration.from_millis(1))\n\n\nrecord = emulator.record(record_fn)"} />

The time passed to `tick` must be an integer multiple of the ultrasound period (25 us).

The output data is a [Polars](https://pola.rs/) `DataFrame`.
For details, refer to the Polars documentation.

## Transducer Table

`Emulator::transducer_table` returns a list of all transducers as a `DataFrame`.
Each row is one transducer, storing the device index (`dev_idx`), the local index within the device (`tr_idx`), the position (`x/y/z[mm]`), and the normal direction (`nx/ny/nz`).
Each row of the drive data and output signal described later corresponds one-to-one with a row of this table.

## Obtaining Drive Data

From the `Record` returned by `record`, the recorded drive data can be obtained.
`phase` / `pulse_width` return a `DataFrame` whose columns are times.
The column names are `phase@<time>[ns]` / `pulse_width@<time>[ns]`, and the time is in increments of the ultrasound period (25 us).

## Sound Field Computation

Passing an observation range (`Range`) and options to `Record::sound_field` yields a sound field computation object.
There are two kinds of options: `RmsRecordOption` (RMS sound pressure) and `InstantRecordOption` (instantaneous sound pressure).

For both, `observe_points` gives the observation point coordinates, and `next` gives the sound field for the specified duration.
`skip` advances time without computing.

Each row of the `DataFrame` returned by `observe_points` is an observation point and corresponds to a row of the sound field `DataFrame`.

<CodeTabs rust={"let rms = record.sound_field(range, RmsRecordOption::default())?;\nlet observe_points = rms.observe_points();\ndbg!(observe_points);"} python={"rng = RangeXY(\n    x=(target[0] - 20.0, target[0] + 20.0),\n    y=(target[1] - 20.0, target[1] + 20.0),\n    z=float(target[2]),\n    resolution=1.0,\n)\nrms = record.sound_field(rng, RmsRecordOption())\nfield = rms.next(Duration.from_micros(25))\nprint(field)"} />

### Observation Range

`Range` represents a set of observation points.
Besides a plane specified by giving two axes a range and fixing the remaining axis to a constant (like `RangeXY`), there are lines along a single axis (`RangeX`, etc.) and cubes spanning all three axes (`RangeXYZ`, etc.).
The order of the axes (`RangeXY` vs. `RangeYX`, etc.) determines the enumeration order of the observation points.
`resolution` is the step width of each axis (mm).

### GPU Backend (Rust version only)

Enabling the `gpu` feature allows the sound field computation to be done on the GPU.
Only when enabled does each option gain a `gpu: bool` field, and setting it to `true` uses the GPU (default is `false`).

```rust
let mut rms = record.sound_field(
    range,
    RmsRecordOption {
        gpu: true,
        ..Default::default()
    },
)?;
```
