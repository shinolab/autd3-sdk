`SamplingConfig` represents the sampling frequency of Modulation or STM.
The sampling frequency must be the ultrasound frequency (40 kHz) divided by an integer.

<CodeTabs rust={"SamplingConfig::new(NonZeroU16::new(10).unwrap());\nSamplingConfig::new(4. * kHz);\nSamplingConfig::new(Duration::from_micros(250));\nSamplingConfig::new(Nearest(4. * kHz));\nSamplingConfig::new(Nearest(Duration::from_micros(250)));"} python={"SamplingConfig(10)\nSamplingConfig(4.0 * kHz)\nSamplingConfig(Duration.from_micros(250))\nSamplingConfig(Nearest(4.0 * kHz))\nSamplingConfig(Nearest(Duration.from_micros(250)))"} csharp={"new SamplingConfig(10);\nnew SamplingConfig(4.0f * kHz);\nnew SamplingConfig(TimeSpan.FromMicroseconds(250));\nnew SamplingConfig(Nearest(4.0f * kHz));\nnew SamplingConfig(Nearest(TimeSpan.FromMicroseconds(250)));"} />

`SamplingConfig::new` accepts `NonZeroU16` / `Freq<f32>` / `Freq<u32>` / `Duration` / `Nearest<Freq<f32>>` / `Nearest<Freq<u32>>` / `Nearest<Duration>`.
An integer frequency such as `4000 * Hz` can be passed in the same way as `4. * kHz`.
All of the above represent 4 kHz (division ratio 10) and are equivalent to one another.

Python takes the division ratio as an `int` and the period as a `Duration`.
C# takes the division ratio as a `ushort` and the period as a `TimeSpan`.

## Internal Representation

`SamplingConfig` can be specified as one of the following. Internally, it is ultimately converted to a division ratio (`u16`).

| Specification method  | Type            |
| --------------------- | --------------- |
| Division ratio        | `NonZeroU16`    |
| Frequency             | `Freq<f32>` / `Freq<u32>` |
| Period                | `Duration` (C#: `TimeSpan`) |

The relationship between the division ratio <Math tex="N" />, the sampling frequency <Math tex="f_s" />, and the sampling period <Math tex="T_s" /> is as follows.

<MathBlock tex="f_s = \frac{40\,\mathrm{kHz}}{N}, \quad T_s = 25\,\mathrm{\mu s} \times N" />

When specified by frequency or period, it is an error if it does not evenly divide 40 kHz (i.e., does not yield an integer division ratio).
`SamplingConfig` does not compute the division ratio at construction; it returns the error when `divide()` / `freq()` / `period()` is called or when a command is encoded (at send time) (the same in Python / C#; the `code` of the Python `Autd3Error` / the `Code` of the C# `Autd3Exception` is `INVALID_ARGUMENT` / `InvalidArgument`).
To round an indivisible value to the nearest division ratio, wrap the frequency/period in `Nearest`.

## Presets

Frequently used constants are provided in advance.

| Constant   | Sampling frequency | Division ratio |
| ---------- | ------------------ | -------------- |
| `FREQ_40K` | 40 kHz             | 1              |
| `FREQ_4K`  | 4 kHz              | 10             |

In C#, they are written as `SamplingConfig.Freq40k` / `SamplingConfig.Freq4k`.
