Holo is a set of Pattern computations for generating multiple focal points (control points) simultaneously.
It optimizes the phase and amplitude of each transducer so that the target sound pressure is obtained at the specified multiple points.

<Install rust="autd3-rs-pattern-holo" python="autd3-pattern-holo" csharp="AUTD3.Pattern.Holo" />

The provided algorithms are as follows.

* [Naive](/autd3-sdk/en/0.12.x/api/compute/holo/naive/) — single-step back-propagation
* [GS](/autd3-sdk/en/0.12.x/api/compute/holo/gs/) — Gerchberg-Saxton method
* [GS-PAT](/autd3-sdk/en/0.12.x/api/compute/holo/gspat/) — GS-PAT method
* [Greedy](/autd3-sdk/en/0.12.x/api/compute/holo/greedy/) — combinatorial optimization that greedily determines the phase

## Common Elements

### AmplitudeTarget

A struct representing a focal point.
It holds a position `point` and a target amplitude `amplitude` (the `point` / `amplitude` properties in Python, `Point` / `Amplitude` in C#).

### Amplitude units `Pa` / `kPa` / `dB`

The target amplitude `Amplitude` is constructed by multiplying an `f32` by an amplitude unit.
Its value is read with `pascal()` (Pa) and `spl()` (dB) (the `pascal` / `spl` properties in Python, `Pascal` / `Spl` in C#).
`Amplitude` supports scalar multiplication (`* f32` / `f32 *`), division (`/ f32`), and comparison (the same in Python / C#).

### IntensityConstraint

The amplitude obtained from the optimization may be an intensity that the transducer cannot output as-is.
Therefore, a constraint is specified for converting the amplitude obtained from the optimization into the transducer intensity to be output.

|                                 |                                                |
|---------------------------------|------------------------------------------------|
| `Normalize`                     | Normalizes by the maximum value                |
| `Multiply(f32)`                 | Multiplies by a coefficient after normalization and clamps |
| `Uniform(Intensity)`            | Sets all transducers to a constant intensity   |
| `Clamp(Intensity, Intensity)`   | Clamps the amplitude to the specified range     |

It is specified via the `constraint` field of each Option.
`greedy` does not optimize the intensities, so it has no `constraint` and takes the intensities as an input.
The default is `Clamp(Intensity::MIN, Intensity::MAX)` for all of `naive` / `gs` / `gspat`.

### Errors

A failure of each function is a `HoloError` in Rust, a `HoloError` in Python (a subclass of `autd3_core.Autd3Error` whose `code` is `INVALID_ARGUMENT`), and an `Autd3Exception` in C# (whose `Code` is `InvalidArgument`).
It fails, for example, when the foci are empty, when the number of devices of an output buffer does not match `geometry`, or when the shape of `mask` does not match `geometry`.

### Directivity

The directivity model of the transducer.
Either the omnidirectional `Sphere` (default) or the real-hardware directivity `T4010A1` can be chosen.
It is specified via the `directivity` field of each Option.

### TransducerMask

Selects the transducers to include in the optimization.
It is specified via the `mask` field of each Option (the default is `AllEnabled`).

* `TransducerMask::AllEnabled` — uses all transducers (default).
* `TransducerMask::Masked(&[Vec<bool>])` — specifies enabled/disabled for each transducer individually.

In Python they are written as `TransducerMask.AllEnabled` / `TransducerMask.masked(rows)`, and in C# as `TransducerMask.AllEnabled` / `TransducerMask.Masked(bool[][])`.
In Python, `mask` does not accept `None` (`TypeError`), so the `None` that [`TransducerGroups.mask(key)`](/autd3-sdk/en/0.12.x/api/compute/pattern/group/) returns for a key assigned to no transducer never silently passes as "all transducers".

### LinAlgBackend (NalgebraBackend)

`naive` / `gs` / `gspat` delegate linear algebra operations to the `LinAlgBackend` trait.
`NalgebraBackend`, which computes on the CPU, is used as the standard implementation.
The backend is passed as the first argument of each function.

`greedy` does not use matrix operations, so it does not take a backend.

Python / C# are fixed to `NalgebraBackend` and do not take a backend argument.

### GPU Backend (WgpuBackend)

`WgpuBackend` is a backend that performs calculations on the GPU (Rust only).

### Batch API

`naive` / `gs` / `gspat` each have a `naive_batch` / `gs_batch` / `gspat_batch` counterpart that solves several independent problems at once.

<CodeTabs rust={"let problems = 64;\nlet foci: Vec<AmplitudeTarget> = (0..problems)\n    .map(|i| AmplitudeTarget {\n        point: center + offset(i as f32 * 0.5 * mm, 0.0 * mm, 0.0 * mm),\n        amplitude: 5e3 * Pa,\n    })\n    .collect();\n\nlet mut phases = vec![geometry.phase_buffer(); problems];\nlet mut intensities = vec![geometry.intensity_buffer(); problems];\ngs_batch(\n    &NalgebraBackend,\n    &geometry,\n    &foci,\n    wavelength,\n    &option,\n    &mut phases,\n    &mut intensities,\n)?;"} python={"problems = 64\nfoci = [\n    AmplitudeTarget(\n        center + offset(i * 0.5 * mm, 0.0 * mm, 0.0 * mm),\n        5e3 * Pa,\n    )\n    for i in range(problems)\n]\n\nphases = [geometry.phase_buffer() for _ in range(problems)]\nintensities = [geometry.intensity_buffer() for _ in range(problems)]\ngs_batch(\n    geometry,\n    foci,\n    wavelength,\n    option,\n    phases,\n    intensities,\n)"} csharp={"var problems = 64;\nvar foci = Enumerable.Range(0, problems)\n    .Select(i => new AmplitudeTarget(center + Offset(i * 0.5f * mm, 0.0f * mm, 0.0f * mm), 5e3f * Pa))\n    .ToArray();\n\nvar phases = Enumerable.Range(0, problems).Select(_ => geometry.PhaseBuffer()).ToArray();\nvar intensities = Enumerable.Range(0, problems).Select(_ => geometry.IntensityBuffer()).ToArray();\nHolo.GsBatch(geometry, foci, wavelength, option, phases, intensities);"} />

The problem count is determined by the length of `phases` / `intensities` (both must have the same length).
The foci are passed as a slice of length equal to the number of problems multiplied by the number of foci per problem.
All problems must have the same number of foci; an error is returned if the length of the slice is not divisible by the problem count.

The batch API is faster only with a GPU backend. A CPU backend (including `NalgebraBackend` used by Python / C#) solves the problems one by one, so it is no faster than calling the function once per problem.
