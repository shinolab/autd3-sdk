## Software control

In AUTD3, a `Pattern` is overwritten each time it is sent.
Therefore, running code like the following moves the focal position roughly once per second.

<CodeTabs rust={"let mut phases = geometry.phase_buffer();\nloop {\n    for sign in [1.0_f32, -1.0] {\n        let target = center + offset((sign * 20.0) * mm, 0.0 * mm, 0.0 * mm);\n        autd3_rs_pattern::focus(\n            &geometry,\n            target,\n            wavelength,\n            &mut phases,\n        );\n        client.send(Pattern::new(&phases, Intensity::MAX)).await?;\n        tokio::time::sleep(Duration::from_secs(1)).await;\n    }\n}"} python={"phases = geometry.phase_buffer()\nwhile True:\n    for sign in (1.0, -1.0):\n        target = center + offset((sign * 20.0) * mm, 0.0 * mm, 0.0 * mm)\n        pattern.focus(\n            geometry,\n            target,\n            wavelength,\n            phases,\n        )\n        await client.send(Pattern(phases, Intensity.MAX))\n        await asyncio.sleep(1.0)"} csharp={"var phases = geometry.PhaseBuffer();\nwhile (true)\n{\n    foreach (var sign in new[] { 1.0f, -1.0f })\n    {\n        var target = center + Offset(sign * 20.0f * mm, 0.0f * mm, 0.0f * mm);\n        Pattern.Focus(\n            geometry,\n            target,\n            wavelength,\n            phases\n        );\n        await client.SendAsync(new Pattern(phases, Intensity.Max));\n        await Task.Delay(TimeSpan.FromSeconds(1));\n    }\n}"} />

The code above controls the timing in software.
Its accuracy depends on the OS and the execution environment, so if higher-precision control is needed, using `FociStm` / `PatternStm` is recommended.

## Hardware control with FociStm

The code that achieves behavior equivalent to the above using [`FociStm`](/autd3-sdk/en/0.13.x/api/command/foci-stm/) is as follows.

<CodeTabs rust={"let points = [\n    ControlPoints::from(center + offset(20.0 * mm, 0.0 * mm, 0.0 * mm)),\n    ControlPoints::from(center + offset(-20.0 * mm, 0.0 * mm, 0.0 * mm)),\n];\nlet config = SamplingConfig::from_freq(1.0 * Hz)?;\nclient.send(FociStm::new(config, &points, FociStmOption::default())).await?;"} python={"points = [\n    ControlPoints(center + offset(20.0 * mm, 0.0 * mm, 0.0 * mm)),\n    ControlPoints(center + offset(-20.0 * mm, 0.0 * mm, 0.0 * mm)),\n]\nconfig = SamplingConfig(1.0 * Hz)\nawait client.send(FociStm(config, points, FociStmOption()))"} csharp={"var points = new[]\n{\n    (ControlPoints)(center + Offset(20.0f * mm, 0.0f * mm, 0.0f * mm)),\n    (ControlPoints)(center + Offset(-20.0f * mm, 0.0f * mm, 0.0f * mm)),\n};\nvar config = new SamplingConfig(1.0f * Hz);\nawait client.SendAsync(new FociStm(config, points, new FociStmOption()));"} />

Because `FociStm` / `PatternStm` loops inside the AUTD3 device, no software loop is needed, and it automatically loops infinitely after being sent.
In addition, the timing is controlled by the timer built into the AUTD3 device, so it is highly accurate and can be specified with a resolution as fine as 25 µs.
However, due to constraints of this timer, there are [frequencies that cannot be output](/autd3-sdk/en/0.13.x/api/basics/sampling-config/#internal-representation).

The switching timing of `FociStm` / `PatternStm` is specified by [`SamplingConfig`](/autd3-sdk/en/0.13.x/api/basics/sampling-config/).

To switch an arbitrary Pattern rather than just a focal point, use [`PatternStm`](/autd3-sdk/en/0.13.x/api/command/pattern-stm/) instead of `FociStm`.
