## API

<CodeTabs rust={"TransportOption {\n    iface,\n    open_timeout,\n    lost_timeout,\n    ack_timeout,\n    send_buffer_bytes,\n    sync_on_open,\n};"} python={"TransportOption(\n    iface=iface,\n    open_timeout=open_timeout,\n    lost_timeout=lost_timeout,\n    ack_timeout=ack_timeout,\n    send_buffer_bytes=send_buffer_bytes,\n)"} csharp={"new TransportOption\n{\n    Iface = iface,\n    OpenTimeout = openTimeout,\n    LostTimeout = lostTimeout,\n    AckTimeout = ackTimeout,\n    SendBufferBytes = sendBufferBytes,\n};"} />

| Field                 | Type                   | Default | Description                                                                                   |
| --------------------- | ---------------------- | ------- | --------------------------------------------------------------------------------------------- |
| `iface`               | `Interface`            | `Auto`  | Destination                                                                                   |
| `open_timeout`        | `Duration`             | 40 s    | Upper bound on the time the open waits |
| `lost_timeout`        | `Duration`             | 100 ms  | A device that has not replied for this long is treated as `Lost` |
| `ack_timeout`         | `Duration`             | 10 ms   | Response-wait timeout |
| `send_buffer_bytes`         | `Option<NonZeroUsize>` | 8192    | Size of the socket send buffer \[B]. `None` leaves the OS default                              |
| `sync_on_open`        | `bool`                 | `true`  | When `false`, open does not wait for the devices to synchronize with one another |

Changing anything other than `iface` is generally not recommended.

:::caution[Windows timer resolution]
The library does not change the timer resolution of Windows (`timeBeginPeriod`).
At the default timer resolution in Windows (typically 15.6 ms), waiting for the replies (the socket receive timeout) is rounded to that granularity, so the judgement of `ack_timeout` and of `lost_timeout` may come late.
If needed, call `timeBeginPeriod(1)` in your process yourself.
:::

## Interface

<CodeTabs rust={"Interface::Auto;\nInterface::Name(\"eth0\".to_string());\nInterface::Addr(\"[::1]:44336\".parse()?);"} python={"Interface.Auto\nInterface.Name(\"eth0\")\nInterface.Addr(\"[::1]:44336\")"} csharp={"_ = Interface.Auto;\n_ = Interface.Name(\"eth0\");\n_ = Interface.Addr(\"[::1]:44336\");"} />

| Value       | Destination                                                                                             |
| ----------- | ------------------------------------------------------------------------------------------------------- |
| `Auto`      | The first network interface on which devices reply                                                      |
| `Name(..)`  | The real devices connected to the network interface with the given name                                 |
| `Addr(..)`  | The given IPv6 address and port. Connect to the [Simulator](/autd3-sdk/en/0.13.x/guide/simulator/) with `[::1]:44336` |
