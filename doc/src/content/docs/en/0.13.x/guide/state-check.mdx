`device_status` of the [`Client`](/autd3-sdk/en/0.13.x/api/basics/client/) lets you monitor whether the communication with the devices is working correctly.

## Obtaining the State

`device_status` returns an array of the state `DeviceStatus` of each device at the time of the call.

`DeviceStatus` holds the following.

* `state`: the state of the device (`DeviceState`).
* `ptp_locked`: whether its PTP is locked.
* `failsafe_active`: whether it stopped its output by the failsafe and has not been released yet

Aggregates such as whether every device is `Ready` or whether any is `Lost` are built from the returned values (see the example below).
`ptp_locked` and `failsafe_active` are taken from the last reply of each device, and both are `false` for a `Lost` device.
Calling it after the `Client` is closed returns an error (`Closed`, or `Network` if it closed on a communication error).

The meaning of each `DeviceState` is as follows.

| State     | Meaning                                                    |
| --------- | ---------------------------------------------------------- |
| `Ready`   | The device replies and its time is synchronized            |
| `Syncing` | The device replies, but its time is still being synchronized |
| `Lost`    | No reply for a certain period of time                      |

When a device in the middle of the chain becomes `Lost`, every device beyond it also becomes `Lost`.
There is no automatic recovery from `Lost`.
Therefore, once a device becomes `Lost`, the only way is to `close` the client and reopen it with `Client::open`.

The following is an example that calls `device_status` at fixed intervals and outputs only when the state changes.
