[`Client`](/autd3-sdk/0.13.x/api/basics/client/) の `device_status` を使うことでデバイスとの通信が正常に動いているかどうかを監視できる.

## 状態の取得

`device_status` は, 呼び出した時点の各デバイスの状態 `DeviceStatus` の配列を返す.

`DeviceStatus` は以下を持つ.

* `state`: デバイスの状態 (`DeviceState`).
* `ptp_locked`: PTP がロックしているか.
* `failsafe_active`: フェイルセーフで出力を止めていて, まだ解除されていないか

全デバイスが `Ready` か, いずれかが `Lost` か, といった集約は返り値から作る (下の例を参照).
`ptp_locked` と `failsafe_active` はデバイスからの最後の返信の値で, `Lost` のデバイスはどちらも `false` になる.
`Client` を閉じた後に呼ぶとエラー (`Closed`. 通信エラーで閉じた場合は `Network`) になる.

`DeviceState`の意味は以下の通り.

| 状態     | 意味                                                                     |
| -------- | ------------------------------------------------------------------------ |
| `Ready`   | 返信があり, 時刻が同期されている                                        |
| `Syncing` | 返信はあるが, 時刻を合わせている途中                                    |
| `Lost`    | 返信が一定時間無い                                                      |

途中の 1 台が`Lost`すると, その機体より先の機体も全て `Lost` になる.
`Lost` からの自動復帰はしない.
そのため, `Lost`した場合は `close` してから `Client::open` で開き直すしかない.

以下は, 一定間隔で `device_status` を呼び, 状態が変化したときだけ出力する例.
