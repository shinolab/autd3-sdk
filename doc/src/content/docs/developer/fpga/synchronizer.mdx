Synchronizer は CPU のデバイス時刻に同期した時刻 `SYS_TIME` を生成するモジュールである.
超音波出力, Modulation, Emission 等はすべてこの `SYS_TIME` を時刻の基準にしている.
デバイス時刻がデバイス間で同期していれば, それらも必然的にすべてのデバイスで同期する.

:::note
信号名の `ECAT_` は, EtherCAT の Sync0 を同期入力に使っていた ファームウェア v0.9.x 以前の名残である.
現在は CPU ボードの Ethernet スイッチ (ETHSW) のタイマから作ったパルスを入れている.
現在のバージョンでは, デバイス間のデバイス時刻の同期は取らない.
:::

このモジュールの動作を理解するためには, 以下の事柄を理解しておく必要がある.

- デバイス時刻 (CPU ボードの ETHSW タイマの時刻) は <Math tex="\SI{1}{ns}" /> 単位の <Math tex="\SI{64}{bit}" /> データである.
    - なお, 時刻基準は 2000 年 1 月 1 日である. <Math tex="\SI{1}{ns}" /> 単位の <Math tex="\SI{64}{bit}" /> なので約 600 年しか使えないが, 事実上問題ない.
- FPGA からは CPU ボードのデバイス時刻に直接アクセスできない.
- CPU ボードは一定の周期で同期パルス (`ECAT_SYNC`) をアサートする. このパルスの立ち上がりはデバイス時刻を参照している.
- 同期パルスの周期は CPU ファームウェアが決める (現在は <Math tex="\SI{1}{ms}" /> 固定).
- CPU ファームウェアはこの周期を `SYS_TIME` の単位に変換して `ECAT_SYNC_CYCLE` として FPGA に渡す (詳細は [CPU ファームウェア](/autd3-sdk/developer/cpu/) を参照).

なお, `SYS_TIME` はデバイス時刻に同期しているが, その単位は <Math tex="1/\SI{20.48}{MHz}" /> で, <Math tex="\SI{57}{bit}" /> となっている.

:::note
`SYS_TIME` を <Math tex="\SI{57}{bit}" /> にしたのは可能な限り使用リソースを少なくするためである.
これにより, オーバーフローまでの期限がデバイス時刻そのものより短く, 約 220 年となるが, これも事実上問題ないだろう.
:::

## 初回同期

`SYS_TIME` の初回の時刻同期は CPU ファームウェアと協調して, 以下の手順で行われる.

1. CPU: 次に同期パルスが立ち上がるデバイス時刻 `ECAT_SYNC_TIME` を求め, FPGA 内の BRAM に書き込む.
    - ただしこの時, 現在時刻が `ECAT_SYNC_TIME` に近すぎる場合は, いったん待機する. これにより, 次の `UPDATE` フラグの書き込み/読み出しが `ECAT_SYNC_TIME` より前に行われることを保証する.
1. CPU: `UPDATE` フラグを FPGA 内の BRAM に書き込む.
1. FPGA: 以下の計算により, 時刻単位を変換しておく.
    <MathBlock tex={String.raw`
    \text{ECAT\_SYNC\_TIME} \times \frac{\SI{20.48}{MHz}}{\SI{1}{GHz}} = 64\times\frac{\text{ECAT\_SYNC\_TIME}}{3125}
    `} />
1. FPGA: `UPDATE` フラグがアサートされている, かつ, `ECAT_SYNC` がアサートされたタイミングで, 単位変換済みの `ECAT_SYNC_TIME` を `SYS_TIME` にセットする.

以上により, FPGA 内部の `SYS_TIME` の時刻がデバイス時刻に同期する.
単位変換は `ec_time_to_sys_time` サブモジュールが行う.

:::note
ただ単にデバイス間を同期することが目的なのであれば, FPGA 内部の時刻をデバイス時刻に同期する必要はない.
そのため, `UPDATE` フラグがアサートされている, かつ, `ECAT_SYNC` がアサートされたタイミングで `SYS_TIME` を <Math tex="0" /> に初期化すれば良い気もするが, これは正しくない.
というのも, デバイス時刻と同期パルスは同期しているが, それ以外の動作 (CPU の処理のタイミング) が同期している保証はないためである.
つまり, `UPDATE` フラグがアサートされるタイミングはすべてのデバイスで異なる可能性がある.
:::

## 定常補正

あとは, `SYS_TIME` をメインクロックでカウントアップすればいい.
しかし, 実際には FPGA のクロックを生成する水晶振動子には個体差があるため, `SYS_TIME` は徐々にずれていってしまう.
定期的に上記と同様のことを行って補正してもいいが, それは大変なので, 同期パルスが周期的に立ち上がるという性質を用いた別の補正方法を採用している.

同期パルスが立ち上がった際, `SYS_TIME` は前回の立ち上がりのときの値に, 同期パルスの周期を足した値になっているはずである.
この周期は `ECAT_SYNC_CYCLE` として CPU から与えられているので, 立ち上がりのたびに次に期待される時刻を

<MathBlock tex={String.raw`
\text{next\_sync\_time} \mathrel{+}= \text{ECAT\_SYNC\_CYCLE}
`} />

と更新すればよい.
同期パルスが立ち上がった際に, この本来あるべき値と実際の `SYS_TIME` の差を取れば, 補正すべき量が求まる.

`SYS_TIME` の補正は, `SYS_TIME` が基準より進んでいる場合 (即ち, 水晶振動子の周波数が基準より高い場合) は `SYS_TIME` のインクリメントを止め, `SYS_TIME` が遅れている場合 (即ち, 水晶振動子の周波数が基準より低い場合) は `SYS_TIME` を <Math tex="+2" /> することにより実行する.
そのため, `SYS_TIME` は逆戻りすることはないが, 一つ飛ばしでカウントアップされる可能性がある.
一つ飛ばしが発生した際は `SKIP_ONE_ASSERT` をアサートする.

補正の残量は `SYNC_TIME_DIFF` として出力され, デバッグ用に [GPIO Output](/autd3-sdk/developer/fpga/gpio-output/) から観測できる.

### 補正タイミングの分散

補正を同期パルスの立ち上がり直後に集中して行うと, 同期パルスの周期に由来する周期的なノイズが生じる.
同期パルスの周期を <Math tex="\SI{500}{us} \times N" /> とすると, 補正の集中により生じるノイズの周波数は <Math tex="1/(\SI{500}{us}\times N) = \SI{2/N}{kHz}" /> である.
特によく使われる <Math tex="N=1" />--<Math tex="4" /> あたりの周波数はヒトの聴覚が比較的敏感な周波数であるため, 補正タイミングを疑似乱数を用いて分散している.

(とはいえ実際にはこのノイズはほとんど聞こえない)
