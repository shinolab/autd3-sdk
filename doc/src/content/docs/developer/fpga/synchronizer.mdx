Synchronizer は CPU のデバイス時刻に同期した時刻 `SYS_TIME` を生成するモジュールである.
超音波出力, Modulation, Emission 等はすべてこの `SYS_TIME` を時刻の基準にしている.
デバイス時刻がデバイス間で同期していれば, それらも必然的にすべてのデバイスで同期する.


このモジュールの動作を理解するためには, 以下の事柄を理解しておく必要がある.

- デバイス時刻 (CPU ボードの ETHSW タイマの時刻) は <Math tex="\SI{1}{ns}" /> 単位の <Math tex="\SI{64}{bit}" /> データである.
    - なお, 時刻基準は `Client` を開いた時点である. <Math tex="\SI{1}{ns}" /> 単位の <Math tex="\SI{64}{bit}" /> なので約 600 年しか使えないが, 事実上問題ない.
- FPGA からは CPU ボードのデバイス時刻に直接アクセスできない.
- CPU ボードは一定の周期で同期パルス (`SYNC_IN`) をアサートする. このパルスの立ち上がりはデバイス時刻を参照している.
- 同期パルスの周期は <Math tex="\SI{1}{ms}" /> 固定である. FPGA はこれを `SYS_TIME` の単位に直した値 (<Math tex="20480" />) を定数 `params::SyncCycleTicks` として持つ

なお, `SYS_TIME` はデバイス時刻に同期しているが, その単位は <Math tex="1/\SI{20.48}{MHz}" /> で, <Math tex="\SI{57}{bit}" /> となっている.

:::note
`SYS_TIME` を <Math tex="\SI{57}{bit}" /> にしたのは可能な限り使用リソースを少なくするためである.
これにより, オーバーフローまでの期限がデバイス時刻そのものより短く, 約 220 年となるが, これも事実上問題ないだろう.
:::

## 初回同期

`SYS_TIME` の初回の時刻同期は CPU ファームウェアと協調して, 以下の手順で行われる.

1. CPU: 次に同期パルスが立ち上がるデバイス時刻を求め, 以下の計算により `SYS_TIME` の単位に変換する.
    <MathBlock tex={String.raw`
    \text{SYNC\_TIME} = \text{time\_ns} \times \frac{\SI{20.48}{MHz}}{\SI{1}{GHz}} = 64\times\frac{\text{time\_ns}}{3125}
    `} />
1. CPU: 変換した値を `SYNC_TIME` として FPGA 内の BRAM に書き込む.
    - ただしこの時, 現在時刻が立ち上がりの 1 周期以上前であれば, いったん待機する. これにより, 次の `UPDATE` フラグが 1 つ手前の立ち上がりより後に届くことを保証する.
1. CPU: 同期の更新要求 (`SYNC_SET`) を FPGA 内の BRAM に書き込む. [Controller](/autd3-sdk/developer/fpga/controller/) がこれを読んで `SYNC_TIME` を取り込み, `UPDATE` フラグをアサートする.
1. FPGA: `UPDATE` フラグを受けた後, 最初に `SYNC_IN` が立ち上がったタイミングで, `SYNC_TIME` を `SYS_TIME` にセットする.
1. CPU: デバイス時刻を読み直し, `UPDATE` フラグが書き込んだ立ち上がりより前に届いたことを確かめる. 間に合っていなければ最初からやり直す.

以上により, FPGA 内部の `SYS_TIME` の時刻がデバイス時刻に同期する.

:::note
ただ単にデバイス間を同期することが目的なのであれば, FPGA 内部の時刻をデバイス時刻に同期する必要はない.
そのため, `UPDATE` フラグを受けた後に `SYNC_IN` がアサートされたタイミングで `SYS_TIME` を <Math tex="0" /> に初期化すれば良い気もするが, これは正しくない.
というのも, デバイス時刻と同期パルスは同期しているが, それ以外の動作 (CPU の処理のタイミング) が同期している保証はないためである.
つまり, `UPDATE` フラグがアサートされるタイミングはすべてのデバイスで異なる可能性がある.
:::

## 定常補正

あとは, `SYS_TIME` をメインクロックでカウントアップすればいい.
しかし, 実際には FPGA のクロックを生成する水晶振動子には個体差があるため, `SYS_TIME` は徐々にずれていってしまう.
定期的に上記と同様のことを行って補正してもいいが, それは大変なので, 同期パルスが周期的に立ち上がるという性質を用いた別の補正方法を採用している.

同期パルスが立ち上がった際, `SYS_TIME` は前回の立ち上がりのときの値に, 同期パルスの周期 (`SyncCycleTicks`) を足した値になっているはずである.
そこで, メインクロックでインクリメントされ, `SyncCycleTicks` で 0 に戻る位相カウンタを持つ.
このカウンタは, ずれが無ければ立ち上がりのときに 0 に戻っているはずである.
ずれがあると, 同期パルスの立ち上がりの時点のカウンタの値 <Math tex="\text{phase}" /> が0以外になり, 補正すべき量が決まる.
正の値は `SYS_TIME` が遅れていること, 負の値は進んでいることを表す.

`SYS_TIME` の補正は, `SYS_TIME` が基準より進んでいる場合 (即ち, 水晶振動子の周波数が基準より高い場合) は `SYS_TIME` のインクリメントを止め, `SYS_TIME` が遅れている場合 (即ち, 水晶振動子の周波数が基準より低い場合) は `SYS_TIME` を <Math tex="+2" /> することにより実行する.
そのため, `SYS_TIME` は逆戻りすることはないが, 一つ飛ばしでカウントアップされる可能性がある.
一つ飛ばしが発生した際は `SKIP_ONE_ASSERT` をアサートする.

補正の残量は `SYNC_TIME_DIFF` として出力され, デバッグ用に [GPIO Output](/autd3-sdk/developer/fpga/gpio-output/) から観測できる.

### 位相カウンタのリセット

立ち上がりの時点のずれが <Math tex="\pm 8191" /> を超えている場合 (同期パルスが張り直された場合など) は, 少しずつ補正するのをやめ, 位相カウンタをその立ち上がりに合わせ直す.

初回同期の後に位相カウンタをリセットした回数は `SYNC_RESYNC_COUNT` として出力される.

### 補正タイミングの分散

補正を同期パルスの立ち上がり直後に集中して行うと, 同期パルスの周期に由来する周期的なノイズが生じる.
同期パルスの周期は <Math tex="\SI{1}{ms}" /> なので, 補正の集中により生じるノイズの周波数は <Math tex="\SI{1}{kHz}" /> である.
これはヒトの聴覚が比較的敏感な周波数であるため, 補正タイミングを疑似乱数を用いて分散している.
補正は平均 3125 クロックに 1 回 (疑似乱数により 1077--5172 クロックの間隔) の頻度で, 1 回につき `SYS_TIME` の 1 単位ずつ行う.

(とはいえ実際にはこのノイズはほとんど聞こえない)
