CPU ボード (AP-RZT-01, Alpha Project) は Renesas RZ/T1 (Arm Cortex-R4F) を搭載している.
これの役割は, ホストから UDP (IPv6 リンクローカル) で受け取ったフレームを解釈し, FPGA 内の BRAM へ書き込むことである.
RZ/T1 内蔵の Ethernet スイッチ (ETHSW) の 2 ポートを使い, デバイスをデイジーチェーンで接続する.

ソースは `firmware/cpu/` 以下にあり, `no_std` Rust で記述されている.
2 つのクレートに分かれている.

- `fw/` (`autd3-cpu-fw`): プロトコル解釈・コマンド処理・FPGA 書き込み, および IPv6 / UDP / ICMPv6 の解析と組み立て (`net`), 列挙と受信振り分け (`node`) などの可搬ロジック.
  ハードウェアには `Port` trait (コマンド層) と `Nic` trait (ネットワーク) 越しにのみアクセスし, `unsafe` を含まない.
  ホストテストと `autd3-rs-firmware-emulator` からも同じコードが使われる.
- `board/` (`autd3-cpu`): 実機ターゲット (armv7r-none-eabi) の staticlib.
  レジスタ定義・BSP・ETHSW / GMAC のドライバ・`Port` / `Nic` trait の実機実装・`main`・panic handler を持ち, `unsafe` はここに閉じ込める.

## 開発環境構築

CPU ファームウェアに関する作業はすべて `autd3-sdk/` ディレクトリ内で `cargo xtask` 経由で実行する.

```bash
cargo xtask cpu build         # 実機用 .bin を生成
cargo xtask cpu flash         # build 後, J-Link で実機へ書き込む
cargo xtask cpu test          # ホスト上の単体テスト (cargo test -p autd3-cpu-fw)
cargo xtask cpu lint          # clippy (fw + board)
cargo xtask cpu format        # rustfmt --check (fw + board)
cargo xtask cpu format --fix  # rustfmt 実書き換え
```

### 必要なツール

| 用途           | ツール                                              |
| -------------- | --------------------------------------------------- |
| 実機ビルド     | Rust ツールチェイン + `rustup target add armv7r-none-eabi`, Arm GNU Toolchain (`arm-none-eabi-gcc`, `arm-none-eabi-objcopy`) |
| 実機書き込み   | J-Link Commander (`JLinkExe`)                       |
| ホストテスト   | Rust ツールチェイン (`cargo test`)                  |
| lint / format  | `clippy`, `rustfmt`                                 |

`arm-none-eabi-` 以外のプレフィックスを使う場合は環境変数 `CROSS_COMPILE` で上書きできる.
`JLinkExe` が PATH に無い場合は環境変数 `JLINK` でパスを指定できる.

### ビルド

`cargo xtask cpu build` は以下を行う.

1. `cargo xtask cpu gen-param` で FPGA の `params.svh` から `fw/src/params.rs` を生成する.
1. `board/` を `armv7r-none-eabi` ターゲットの staticlib (`libautd3_cpu.a`) としてビルドする.
1. `arm-none-eabi-gcc` で `platform/autd3-platform.o` とリンカスクリプト `platform/autd3-cpu.ld` を用いてリンクする.
1. `objcopy` で `build/autd3-cpu.bin` を生成する.

`platform/autd3-platform.o` はローダ・スタートアップ・シリアルフラッシュドライバを含む非公開コードのビルド済みオブジェクトである.
スタートアップは `board/src/lib.rs` の `main` を呼び, 以後の初期化とメインループはすべて Rust 側で行う.
ビルドの最後に, イメージ内のトランスポートマーカ (UDP 版であることを示す) を検査する.

### 実機書き込み

`cargo xtask cpu flash` は J-Link を JTAG 接続し, `autd3-cpu.bin` を `0x30000000` へロードして実行する.
デバイスは `R7S910018_R4F` として認識される.

### ホストテスト

`fw/` は `Port` trait (`fpga_write` / `fpga_read` / `memory_barrier` など) と `Nic` trait 以外のハードウェア依存を持たない.
`cargo xtask cpu test` では `fw/src/tests/mock.rs` の `MockPort` がこれを置き換え, FPGA への書き込みを記録する.
`fw/src/tests/` がプロトコル層 (`Cpu::recv_frame` / `Cpu::process_one`) の振る舞いを, `fw/src/net` と `fw/src/node` のテストがネットワーク処理と列挙の振る舞いを検証する.

## フレーム処理

ホストは送るものがあるときに, 各デバイスへ 1 つの UDP データグラム (デバイス側ポート 44336) を送る.
データグラムは 4 byte のヘッダ (版数・種別・メッセージ ID) の後ろに最大 1448 byte のフレームを持つ.
送るものが無い間は, フレームの代わりに生存確認 (`Heartbeat`) が届く.

受信フレームは先頭が `seq` (1 byte), `cmd` (1 byte) で, 残り (最大 1446 byte) がペイロードである.
ホストはペイロード末尾の 0 を省いて送るので, デバイスは受け取らなかった部分を 0 で埋めてからコマンド層 (`Cpu::recv_frame`) へ渡す.
各フレームの扱いを終えた時点で, `ack` (1 byte)・`status` (エラーコード, 1 byte)・読み出し値 (最大 32 byte) を載せた返信を 1 回送る.
返信にはこのほか, デバイスの状態フラグ・ID・デバイスの時刻が載る.

受信割り込みの中で扱いが終わるもの (再送・`CMD_RESET`・Low Latency モードでの処理・`Heartbeat`) は割り込みの中で返信し,
FIFO に積んだフレームはメインループが処理した後に, 割り込みを禁止した区間で返信する.
再送と `Heartbeat` への返信は割り込みの中で返るので, メインループが長い処理で止まっていても返り続ける.

同じ `seq` かつ同じ `cmd` のフレームは再送とみなして無視する (返信だけを返す).

フレームの処理方式には 2 つのモードがあり, `SetMode` コマンド (`CMD_SET_MODE`) でセッション全体を切り替える.

<Mermaid
  title="フレーム処理モード"
  code={`flowchart TB
  RX["recv_frame (Ethernet 受信割り込み)"]
  MODE{"mode"}
  FIFO[("FIFO (深さ 8)")]
  MAIN["app_process_pending (メインループ)"]
  HANDLE["handle_frame"]
  RX --> MODE
  MODE -- "MODE_LOW_LATENCY" --> HANDLE
  MODE -- "MODE_FIFO" --> FIFO
  FIFO --> MAIN --> HANDLE`}
/>

- `MODE_FIFO` (既定): 受信フレームを深さ 8 のリングバッファに積むだけで割り込みを抜け, メインループが処理して返信する. 割り込み時間が短く済むが, `ack` が返るまでの遅延が増える.
- `MODE_LOW_LATENCY`: 受信割り込みの中で直接処理する. 遅延は小さいが, 処理時間の長いコマンドが受信割り込みを長引かせる.

FIFO が満杯の場合, フレームは捨てられ, 返信も送らない.
`ack` が進まないため, クライアント側が再送する (クライアントは既定で 7 フレームまでしか同時に送らない).

`CMD_RESET` だけはモードに関わらず割り込み内で即座に処理され, FIFO も破棄される.

## エラー通知

`handle_frame` はコマンドを実行し, エラーがあればエラーコードをラッチする.
ラッチされたコードは `CMD_READ_ERROR_DETAIL` で読み出せる.

| コード | 名前                           | 意味                                       |
| ------ | ------------------------------ | ------------------------------------------ |
| `0x00` | `ERR_NONE`                     | エラーなし                                 |
| `0x01` | `ERR_UNKNOWN_CMD`              | 未知のコマンド                             |
| `0x02` | `ERR_INVALID_PAYLOAD`          | ペイロードの長さ・オフセットが不正         |
| `0x03` | `ERR_INVALID_DATA`             | データの値が不正                           |
| `0x04` | `ERR_INVALID_SILENCER_SETTING` | Silencer の設定が厳格モードの条件を満たさない |
| `0x05` | `ERR_INVALID_TRANSITION_MODE`  | 遷移モードと繰り返し回数の組み合わせが不正 |
| `0x06` | `ERR_MISS_TRANSITION_TIME`     | `SysTime` 遷移の指定時刻が近すぎる・過去である |
| `0x07` | `ERR_FPGA_TIMEOUT`             | FPGA が制御フラグを期限内にクリアしない     |
| `0x08` | `ERR_SYNC_NOT_READY`           | 同期パルスがまだ動いていない (時刻合わせ前) |
| `0x09` | (欠番)                         | Firmware v0.9.0 までの `ERR_INVALID_SYNC0_CYCLE`. 同期パルスの周期はファームが決めるので発生しない |

## FPGA への書き込み

FPGA は CS1 空間 (`0x44000000`) にマップされた <Math tex="\SI{16}{bit}" /> 幅のメモリとして見える.
`Port` trait の `fpga_write` / `fpga_read` (実機実装は `board/src/port.rs` の `HwPort`) がこの領域への volatile アクセスを担う.

`fpga::write(select, addr, value)` は `select` (BRAM 選択, 2 bit) と `addr` (14 bit) を連結してアドレスを作る.
詳細は [Memory](/autd3-sdk/developer/fpga/memory/) を参照されたい.

:::caution
FPGA 側の「書き込み先を切り替えるレジスタ」(`MOD_MEM_WR_BANK` / `MOD_MEM_WR_PAGE` / `PATTERN_MEM_WR_BANK` / `PATTERN_MEM_WR_PAGE`) は BRAM と違いラッチされない.
そのため, これらを書き換える前後ではメモリバリア (`Port::memory_barrier`, `dmb` 命令) が必要である.
:::

設定値の反映は制御フラグ経由のハンドシェイクで行う.
`set_and_wait_update(flag)` が `ADDR_CTL_FLAG` の該当ビットを立て, FPGA の [Controller](/autd3-sdk/developer/fpga/controller/) がそれをクリアするまでポーリングする.

## 同期

FPGA の同期入力 (`CAT_SYNC0` ピン) には, ETHSW のタイマから作った同期パルスを入れる.
ホストは `Client` (`UdpBus`) を開くときに全デバイスへ現在時刻を送り (`SetTime`), 各デバイスは ETHSW のタイマをその時刻に合わせたうえで,
タイマの SYNCOUT (<Math tex="\SI{500}{us}" /> 周期) から ELC → MTU → PPG を経て, 立ち上がりが <Math tex="\SI{1}{ms}" /> 境界に乗る <Math tex="\SI{1}{ms}" /> 周期のパルスを作る.
現在のバージョンでは, デバイス間のタイマの同期は取らない.

`CMD_SYNCHRONIZE` は以下を行う.

1. 同期パルスの周期 (ファームの定数 <Math tex="\SI{1}{ms}" />) を FPGA内部の`SYS_TIME` の単位 (<Math tex="\SI{20.48}{MHz}" />) へ変換する

    <MathBlock tex={String.raw`
    \text{cycle\_ticks} = \text{cycle\_ns} \times \frac{\SI{20.48}{MHz}}{\SI{1}{GHz}} = 64 \times \frac{\text{cycle\_ns}}{3125}
    `} />

1. 次に同期パルスが立ち上がるデバイス時刻 (現在時刻から <Math tex="\SI{250}{us}" /> 以上先の最初の <Math tex="\SI{1}{ms}" /> 境界) を求める.
    - 同期パルスがまだ動いていない場合は `ERR_SYNC_NOT_READY` を返す
1. その時刻を `ADDR_SYNC_TIME_*` へ, 変換した周期を `ADDR_SYNC_CYCLE_*` へ書き込む (FPGA のレジスタ名は `ECAT_SYNC_*`).
1. `SYNC_SET` フラグを立て, FPGA の [Synchronizer](/autd3-sdk/developer/fpga/synchronizer/) が `SYS_TIME` をセットするのを待つ.

## バンク遷移の検証

遷移モードと繰り返し回数の組み合わせには制約がある.
無限ループ (`REP == 0xFFFF`) では `Immediate` / `Ext` のみ, 有限ループでは `SyncIdx` / `SysTime` / `Gpio` のみが有効である.
`transition_mode_violates_loop()` がこれを検証し, 違反すれば `ERR_INVALID_TRANSITION_MODE` を返す.

また `SysTime` 遷移では, 指定時刻が現在時刻から <Math tex="\SI{10}{ms}" /> 以内 (または過去) の場合, FPGA が遷移を取りこぼす可能性がため, `ERR_MISS_TRANSITION_TIME` を返す.
