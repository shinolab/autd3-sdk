クライアントライブラリは Rust で実装されており, 各言語バインディングはそれを包む形で提供される.

## クレート構成

<Mermaid
  title="クレート依存関係"
  code={`flowchart BT

| クレート                     | 役割                                                                 |
| ---------------------------- | -------------------------------------------------------------------- |
| `autd3-rs-core`              | 基盤層. geometry / value / params / protocol と通信の観測型 (`bus`). |
| `autd3-rs`                   | クライアント本体                                                      |
| `autd3-rs-pattern`           | 位相・振幅パターンの計算 (単一焦点等).                                |
| `autd3-rs-pattern-holo`      | 多焦点音場再構成. 理論は[理論と考察](/autd3-sdk/theory/holo/)を参照.  |
| `autd3-rs-modulation`        | AM 波形計算.                                                          |
| `autd3-rs-firmware-emulator` | 実 CPU ファームウェアのクレート (`autd3-cpu-fw`) をリンクし, Rust による FPGA エミュレータと組み合わせる |

## タスクモデル

`Client` はタスクを持たない薄いソケットで, 送信も受信も呼び出し側のタスクがその場で行う.

<Mermaid
  title="タスクモデル"
  code={`flowchart LR
  U["ユーザーのタスク (非同期)"]
  D["デバイス"]
  U -- "send_frame / send_heartbeat: UDP フレーム" --> D
  D -- "recv / collect: UDP 返信" --> U`}
/>

- **送信**: `send_frame` / `send_heartbeat` を呼んだタスクがその場で全デバイスへ送り, `msg_id` を返す. 返信は待たない. tokio を前提とする.
- **受信**: `recv` / `collect` を await している間だけソケットを読む. `collect` は `msg_id` が一致する返信を全デバイスぶん集めて `Response` を返す. 期限は持たない (上限はユーザーが付ける).

`Client` が持つのは `Geometry`・通信層の `Channel` (`udp/channel.rs`, crate 内部)・`msg_id` の採番 (`AtomicU16`)・デバイス時刻の推定 (`DeviceClock`) だけである.
`Channel` は普通の UDP ソケットで各デバイスへデータグラムを 1 つずつ送り, 届いた返信を 1 つずつ返す口だけを持ち, デバイスの状態は持たない.
いつ送るか (窓)・返信待ちの上限・途絶の判定・生存確認はユーザーが決める (streaming の照合には `InflightFrames` を使える).
Link のような差し替え可能な通信路の抽象は無い.

## ユーザー API からデバイスまで

ユーザーが渡したコマンドは, フレーム列へ実体化されたうえで `send` を呼んだタスクから送出される (返信を待たずに送ってよいのは `MAX_INFLIGHT` (= 7) フレームまで).

<Mermaid
  title="コマンドの流れ"
  code={`flowchart LR
  CMD["Command"]
  FR["Frames"]
  DEV["デバイス"]
  CMD -- "Frames::encode" --> FR
  FR -- "Client" --> DEV`}
/>

- [エンコーダ](/autd3-sdk/developer/software/encoder/): コマンドを送信フレームへ変換する
- [送信処理](/autd3-sdk/developer/software/transmission/): フレームを送出し, 返信を `msg_id` で照合して完了させる

## バインディング

| 言語       | 方式             | 備考                                                       |
| ---------- | ---------------- | ---------------------------------------------------------- |
| Rust       | -                | 本体.                                                      |
| Python     | PyO3 + maturin   | C FFI を経由せず Rust API を直接ラップする.                |
| C# / Unity | C FFI + P/Invoke | `bindings/ffi/` の cdylib 群を参照する.                    |

`bindings/ffi/` は言語中立な C ABI の cdylib 群であり, クレート毎に分かれている.
不透明ハンドルと共有 ABI 契約は `autd3-ffi-abi` が定義する.

## ビルド

開発タスクはすべて `cargo xtask` で実行する.

```bash
cargo xtask rust build   # ワークスペース全体ビルド
cargo xtask rust test    # 全テスト
cargo xtask rust lint    # clippy --all-targets -- -D warnings
cargo xtask rust format  # rustfmt --check
```
