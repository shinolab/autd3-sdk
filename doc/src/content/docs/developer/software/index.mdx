クライアントライブラリは Rust で実装されており, 各言語バインディングはそれを包む形で提供される.

## クレート構成

<Mermaid
  title="クレート依存関係"
  code={`flowchart BT

| クレート                     | 役割                                                                 |
| ---------------------------- | -------------------------------------------------------------------- |
| `autd3-rs-core`              | 基盤層. geometry / value / params / protocol / error と通信の観測型 (`bus`). |
| `autd3-rs`                   | クライアント本体. UDP 通信 (`udp`) とデバイスエミュレータ (feature `emulator`) を含む. |
| `autd3-rs-pattern`           | Emission パターン計算 (焦点合成等).                                   |
| `autd3-rs-pattern-holo`      | 多焦点音場再構成. 理論は[理論と考察](/autd3-sdk/theory/holo/)を参照.  |
| `autd3-rs-modulation`        | AM 波形計算.                                                          |
| `autd3-rs-firmware-emulator` | 実 CPU ファームウェア (`autd3-cpu-fw`) のソースを取り込み, Rust による FPGA エミュレータと組み合わせる. |

## スレッドモデル

デバイスとの送受信と, ユーザーの非同期 API を分離している.

<Mermaid
  title="スレッドモデル"
  code={`flowchart LR
  U["ユーザースレッド (非同期)"]
  IO["I/O スレッド (受信・生存確認)"]
  D["デバイス"]
  U -- "UDP: フレーム" --> D
  D -- "UDP: 返信" --> IO
  IO -- "oneshot: 完了通知" --> U`}
/>

- **ユーザースレッド**: `send` を呼んだスレッドがその場で全デバイスへフレームを送り, `.await` で完了通知を待つ. 待機は自前の `Waker` 実装だけで組まれており, 特定の非同期ランタイムに依存しない.
- **I/O スレッド**: `Client` が持つ 1 本の OS スレッド. 返信を読んで `msg_id` で送信中のフレームへ照合し, 全デバイスの返信が揃ったら完了を通知する. 送るものが無い間は `heartbeat` ごとに生存確認を送る.

`UdpBus` は要求駆動の口 (`send` / `heartbeat` / `recv`) だけを持ち, 送信と受信を別スレッドから同時に呼べる.
普通の UDP ソケットで各デバイスへフレームを 1 つずつ送り, 届いた返信を 1 つずつ返す. いつ送るか (窓・`Reset`・生存確認) は `Client` が決める.
Link のような差し替え可能な通信路の抽象は無い.

## ユーザー API からデバイスまで

ユーザーが渡したコマンドは, フレーム列へ実体化されたうえで `send` を呼んだスレッドから送出される (返信を待たずに送ってよいのは `max_inflight` フレームまで).

<Mermaid
  title="コマンドの流れ"
  code={`flowchart LR
  CMD["Command"]
  FR["Frames"]
  DEV["デバイス"]
  CMD -- "Frames::encode" --> FR
  FR -- "Client" --> DEV`}
/>

- [エンコーダ](/autd3-sdk/developer/software/encoder/): コマンドを送信フレームへ変換する
- [送信処理](/autd3-sdk/developer/software/transmission/): フレームを送出し, 返信を `msg_id` で照合して完了させる

## バインディング

| 言語       | 方式             | 備考                                                       |
| ---------- | ---------------- | ---------------------------------------------------------- |
| Rust       | -                | 本体.                                                      |
| Python     | PyO3 + maturin   | C FFI を経由せず Rust API を直接ラップする.                |
| C# / Unity | C FFI + P/Invoke | `bindings/ffi/` の cdylib 群を参照する.                    |

`bindings/ffi/` は言語中立な C ABI の cdylib 群であり, クレート毎に分かれている.
不透明ハンドルと共有 ABI 契約は `autd3-ffi-abi` が定義する.

## ビルド

開発タスクはすべて `cargo xtask` で実行する.

```bash
cargo xtask rust build   # ワークスペース全体ビルド
cargo xtask rust test    # 全テスト
cargo xtask rust lint    # clippy --all-targets -- -D warnings
cargo xtask rust format  # rustfmt --check
```
